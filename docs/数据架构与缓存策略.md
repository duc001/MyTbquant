# 数据架构与缓存策略

> 适用范围：期权卖出策略（sell_option）的取数层（fetchers）与运行流程（strategy/cli `scan/check/...`）。
> 目的：把"哪些数据稳定 / 中间 / 实时""缓存落在哪""哪些能离线跑"一次说清，支撑**预取 + 质检 + 纯缓存运行**两阶段流程。

---

## 1. 核心机制

### 1.1 取数单元（D01–D18）
按需求 §6.1 数据项总表，一个 D 项一个模块，位于 `sell_option/fetchers/`：

| 模块 | 含义 |
|---|---|
| `d01_variety_list` | 品种列表 |
| `d02_symbol_template` | symbol 编码模板 |
| `d03_index_symbol` | 品种 → 888/9888 主连指数 symbol |
| `d04_margin_rate` | 保证金率 |
| `d05_combo_discount` | 组合折扣 |
| `d06_option_chain` | 期权链（结构 + 实时 quote） |
| `d07_candidate_months` | 候选月（按 DTE 推导） |
| `d08_spot_price` | 现货/合约现价 |
| `d09_d10_premium` | 权利金（收盘/盘中） |
| `d11_contract_multiplier` | 合约乘数 |
| `d12_index_daily` | 主连后复权日线（≥250 条） |
| `d13_iv_snapshot` | IV 快照 |
| `d14_contract_oi` | 合约持仓量 OI |
| `d15_calendar` | 交易日/节假日/FOMC 日历 |
| `d16_positions` | 账户持仓 |
| `d17_capital_pool` | 资金池配置 |
| `d18_budget` | 预算档配置 |

### 1.2 缓存键：`pull_date`
所有落盘缓存统一按 **`(symbol, pull_date)`** 查询，其中
`pull_date = pull_date_for(today)` = 最近交易日（`fetchers/_trading_day.py`）。
效果：**同一交易日重跑命中缓存、秒回；跨交易日自动失效重拉**，不会出现"用旧数据冒充新决策"。

### 1.3 缓存库清单（`sell_option/data/`）
| 文件 | 承载数据项 | 主键 |
|---|---|---|
| `daily.db` | D12 主连后复权日线 | `(symbol, pull_date)` |
| `spot.db` | D08 现货/合约现价（收盘） | `(symbol, pull_date)` |
| `premium.db` | D09/D10 收盘权利金 + D14 的 OI 列 | `(symbol, pull_date)` |
| `iv_snapshot.db` | D13 IV 快照 | `(variety, snapshot_date)` |
| `calendar.db` | D15 FOMC/事件日历 | `pull_date` |
| `positions.db` | D16 持仓 | 账户级 |

> 注：`d06` 期权链结构、`d01/d02/d03/d04/d05/d07/d11/d17/d18` 多为规则/配置派生或人工维护静态表，**不落上述 sqlite**，每次运行实时推导或读配置/边界表（`docs/品种边界表.md`）。

### 1.4 内建数据质检（Verdict）
每个 fetcher 产物自带 `Verdict`（见 `fetchers/models.py`）：
`PASS`（可用）/ `WARN`（达标但不足，如数据偏少）/ `MISSING`（拿不到，**绝不用代理数据冒充**）/ `FAIL`（硬否决，仅检查层用）。
→ 这就是"检查数据"的现成抓手，可直接聚合成"数据就绪报告"。

### 1.5 现有预取/刷新入口
- `_prewarm`（盘后/假日）：批量预取 **现货(D08→spot.db) + 指数日线(D12→daily.db)**，写入缓存后 `run_pool` 走缓存秒回。
- `refresh [--all]`：仅刷新 **D12 日线缓存**（强制全量 / 只补缺）。
- `collect_oi`：实时采集某品种候选月 OI，**不落盘**（仅展示供 #2 复核）。
- 权利金/IO：由 `run_pool` 逐品种取数并写入 `premium.db`（按 `pull_date`），同日重跑命中。

## 2. 逐表稳定性分类（一个一个表整理）

| 数据项 | 性质 | 缓存库 | 能否纯缓存 | 说明 |
|---|---|---|---|---|
| D01 品种列表 | 稳定 | 内存/规则 | ✅ 长期 | 规则派生，几乎不变 |
| D02 symbol 模板 | 稳定 | 规则 | ✅ 长期 | 编码规则 |
| D03 指数 symbol | 稳定 | 规则 | ✅ 长期 | 品种→888/9888 |
| D04 保证金率 | 稳定 | — | ✅ 长期 | 交易所规则，偶变 |
| D05 组合折扣 | 稳定 | — | ✅ 长期 | 交易所规则 |
| D11 合约乘数 | 稳定 | — | ✅ 长期 | 合约属性 |
| D15 日历/FOMC | 稳定 | calendar.db | ✅ 长期 | 年度/人工维护 |
| 边界表 | 稳定 | 文档 | ✅ 长期 | `docs/品种边界表.md` 人工维护 |
| D17 资金池 | 稳定 | 配置 | ✅ 长期 | 运行配置 |
| D18 预算档 | 稳定 | 配置 | ✅ 长期 | 运行配置 |
| **D12 主连后复权日线** | 中间 | daily.db | ✅ **同交易日** | ≥250 bars 历史，盘后用当日快照即可 |
| **D08 现货价（收盘）** | 中间/实时 | spot.db | ✅ 收盘(同交易日)；盘中 live | 盘后日报用收盘值足够 |
| **D06 期权链结构** | 中间 | — | ⚠️ 结构可缓存，quote 不 | 月份/行权价会变 |
| **D09/D10 收盘权利金** | 中间/实时 | premium.db | ✅ 收盘(同交易日)；tick 不 | 代码注释明示 **tick 盘口不缓存** |
| **D13 IV 快照** | 中间/实时 | iv_snapshot.db | ✅ 日快照；盘中需新鲜 | |
| **D14 合约 OI** | 实时 | premium.db(oi列) | ⚠️ 盘后合并写；盘中独立取 | `collect_oi` 实时不落盘 |
| **D16 持仓** | 实时 | positions.db | ❌ 账户状态 live | 平仓扫描必须 live |

**结论**：稳定 + 中间（收盘）数据均可缓存并按交易日复用；真正"不能缓存"的只有**盘中 tick 盘口、实时 OI、实时 IV、实时持仓**——且本工具 `scan` 是"盘后生成次日候选日报"，用的正是当日收盘快照，故对主场景完全成立。

## 3. 两阶段运行设计（目标态）

### Phase 1 — `prefetch`（预取 + 质检）
- 盘后/假日运行，把**稳定 + 中间（收盘）** 数据全量拉进缓存（`refresh` 仅覆盖 D12，需扩到 spot/premium/iv/calendar/positions 等）。
- 产出 **数据就绪报告**：逐品种汇总 Verdict（PASS / MISSING 将被跳过），让人一眼看到"哪些数据齐了、哪些缺"。

### Phase 2 — `scan --offline`（纯缓存运行）
- 绝不触碰 tbpy，全部走缓存；报告明确打 `缓存日=YYYY-MM-DD` 戳，避免误当实时。
- 适用：管线自测、tbpy 不可用时的兜底、日报重渲染。

### 就绪门禁
- prefetch 后若存在 MISSING 品种，`scan` 自动跳过并告警（绝不拿缺数据冒充，见 §1.4）。

## 4. 实时数据边界（澄清"不能从缓存获取"）

| 场景 | 能否纯缓存 | 原因 |
|---|---|---|
| 盘后生成次日候选日报 | ✅ 可 | 用当日**收盘快照**，本就按交易日缓存 |
| 盘中实时下单决策 | ❌ 不可 | tick 盘口 / 实时 OI / 实时 IV / 实时持仓必须 live |
| 持仓平仓扫描（exit） | ❌ 不可 | D16 账户状态 live |

→ 两阶段方案**不消灭实时取数**，而是把"能预先下载的部分"前置并质检，把"必须实时的部分"留在 Phase 2 的 live fetch（可节流）。

---

## 5. 风险与注意
1. **跨交易日自动失效**：`pull_date` 机制保证旧缓存不残留（见 §1.2），不要手动跨日复用缓存文件。
2. **离线报告必须打时间戳**：`scan --offline` 产物要标注缓存日，防止把快照当实时。
3. **tick 盘口不缓存**：`premium.db` 只存收盘权利金；盘中权利金需 live 取（见 §2 注释）。
4. **缓存写入幂等**：各 repo 用 `INSERT OR REPLACE`，重跑安全；但注意 D09/D14 共用 `premium.db` 的 oi 列——`combo_oi_close_batch` 写后勿重复 `repo.save` 覆盖成 NULL（代码注释已警示）。
