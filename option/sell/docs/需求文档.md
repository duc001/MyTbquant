# option.sell 需求文档（v2 重写基线）

> 本文是 `option.sell`（期权卖方策略）重写版的需求基线，**全新设计，不沿用旧系统 `strategies/sell_option` 的文档 / 代码 / 数据**（仅作背景，新系统完成后即删除）。库表与字段细节以 `库表设计.md` 为准，本文不重复。「待定 / 待你拍板」处随重写推进填充。

## 一、背景与目标
- v1（`strategies/sell_option`）运行暴露数据与架构问题 → 停止维护，本目录从零重写。
- 目标：**只读决策支持工具**——数据分析 + 生成报告 + 交易提醒（事件 / 长假 / 破位 / 到期）。
- 不接账户、不下单、不自动交易；人工看报告自行决策与下单。
- 范围：期权卖方**垂直价差 / 铁鹰**（带保护腿、封顶、绝不裸卖）。

## 二、必须坚守的域约束（v2 重新实现，不照搬旧代码）
> 从 v1 踩坑沉淀的**通用域规则**（与实现无关），v2 须以全新代码满足，而非复制旧实现。
1. **价格口径两分，绝不混用**：连续指数（后复权）只用于相对指标（收益率 / 波动率 / 趋势 / 区间位置）；真实月份合约（不复权）用于一切绝对价（现价 / 行权价 / 权利金 / 保证金 / 安全垫 / 封顶 / 肥瘦）。混用即缺陷。
2. **缺数如实判 MISSING**，绝不用代理数据冒充、不静默降级成 PASS。
3. **绝不裸卖**，全部封顶价差；单笔最大亏损 =（价差宽度 − 净权利金）× 乘数，封死。
4. **取数归属交易日（`pull_date`）严格口径**：缓存按最近交易日查 / 落，跨日自动失效，不拿旧数据冒充新决策；盘中实时价不缓存。
5. **离线 / 缓存产物必须打时间戳**，避免误当实时。

## 三、v1 已知问题（v2 必须规避）
- **数据维护时机错位**：数据在"生成报表时才拉"，拉取与报表强耦合；源一不稳报表质量即被拉垮，且无法在数据层先发现问题。
- **脏数据检不出**：缺独立质检环节，检查逻辑照单全收 → 结论失真。
- **缺失 / 非终态数据无机制维护**：拉到的不一定齐、不一定终态（盘后未结算 / 盘中未定稿），旧流程直接拿去出报表。
- **根因**：拉取、质检、出报混在同一时机，缺阶段隔离与就绪门禁。→ v2 解法见 §六 三阶段流水线 + §6.5 就绪登记表。

## 四、产品定位（方向性）
- 只读决策支持；"可开 / 不可开"仅是机械化检查结论，非投资建议；下单前人工复核盘口与保证金实数。

## 五、策略核心（方向性）
- 适用场景：震荡市收取时间价值 + 波动率下降收益。
- 卖平值 / 虚值价差（收时间价值）+ 买入更虚值保护腿（防单边风险）→ 垂直价差 / 铁鹰。
- **单卖**＝一侧垂直价差（2 腿）；**双卖 / 铁鹰**＝上下两侧价差（4 腿）＝两个单卖；均带保护腿、最大亏损封死、不裸卖。

## 六、数据治理：三阶段流水线（核心架构）
> 数据生命周期拆成三个**相互独立、可单独运行、阶段间用门禁隔离**的阶段；阶段三**不得**在阶段二未通过时运行。

### 6.1 阶段一：拉取数据（fetch / prefetch）
- 与报表**解耦**：可独立、可定时（盘前 / 盘后预取）运行，结果落本地缓存。
- 多源失败逐源降级、不崩；断点续取；按 `pull_date` 严格缓存（承接 §二.4）。
- **只负责"拿回来"，不做任何业务判定**。
- 每完成一表拉取即向 `data_state_check` 写 / 更新该表记录（status: init → fetching），供阶段二 / 三监控。

### 6.2 阶段二：检查数据（validate / quality gate）—— v1 缺失的关键环节
- 数据进入策略逻辑前先做质量校验，结果回写 `data_state_check`（status: normal / abnormal），作为阶段三门禁唯一事实来源。
- 校验维度（规则 / 阈值待细化，但本阶段必须存在）：
  - **完整性**：必填字段 / 数据项是否齐全（据 `data_storage_rule` 声明 + `future_info` 实体数算应有条数对账），缺失 → 标 MISSING、不进报表；
  - **脏数据**：数值越界、符号异常、重复 / 冲突、口径串用（指数价当真实价等，承接 §二.1）静态检出；
  - **终态性**：是否已终态 / 已结算，非终态明确标注、不混入终态结论；
  - **一致性**：跨源（tbpy / openvlab / 新浪）同标的取值是否冲突，冲突以权威源为准并报警。

### 6.3 阶段三：生成报表（report）
- 仅消费阶段二判定 ready 的数据；对缺失 / 脏 / 非终态项如实标注（MISSING / 待复核），**绝不拿未过检数据硬出结论**。
- 报表不含取数逻辑，纯消费已质检数据。

### 6.4 门禁（gate）
- 阶段三**不可**在阶段二未通过时运行；可先单独跑一 + 二出「数据就绪报告」再决定。
- 判定依据 = `data_state_check` 中对应表 `status='normal'`；状态表持久化，可随时查各表准备情况。
- 离线（纯缓存）模式同样先过阶段二，缺失 / 非终态项照常标注、打时间戳（承接 §二.5）。

### 6.5 中央就绪登记表（整体管理 / 监控）
- 全部数据统一存单一库 `option.db`（业务表与控制面表同库、以表逻辑区分，见表设计 §一）。
- 实现即 `库表设计.md` §2.3 `data_state_check`（每表一行，四态 init / fetching / normal / abnormal；normal 放行、abnormal 阻塞 + 报警）+ §2.4 `data_pull_detail`（每次拉取 / 校验一行明细流水）；是 §6.4 门禁唯一事实来源、"数据就绪报告"底座，按 `table_ref` 查即得各表状态看板（v1 缺失）。
- **须与 §七 应有清单对账**：状态表只反映"已被拉取 / 校验的表"，整张表 / 整个品种静默漏拉时状态表无行、单靠它发现不了。

### 6.6 全局配置表 global_config
- 系统级固定配置收口一张 KV 表（`库表设计.md` §2.1），避免散落代码常量 / 环境变量；分组以 key 前缀体现（`source.` / `schedule.` / `gate.` / `budget.` / `account.` 等）。
- 与就绪表（运行态）、应有清单（数据契约）并列，三者同处 `option.db` 构成控制面：全局配置＝"系统怎么跑"，应有清单＝"该有哪些数据"，就绪表＝"数据现在怎样"，不重叠。
- 逐品种固定参数（乘数 / 保证金 / 组合优惠）单列 `future_info`，不塞进本表，避免万物桶。

## 七、应有清单（数据契约 / 阶段零）
- **为何需要**：就绪表发现不了"整张表 / 整个品种没被拉"，须有一张"本应存在什么"的清单与之对账，才能覆盖缺失 / 脏 / 非终态三类问题。应有清单＝期望维度（标准答案），就绪表＝实际维度（实时考卷）。
- 落库为 `option.db` 的 `data_storage_rule`（`库表设计.md` §2.2），一取数单元一行；以 `future_info` 全部 `main_index_symbol` 实体**动态枚举**算应有实体，驱动应到 vs 实到对账与终态判定。
- 期货品种信息表 `future_info`（`库表设计.md` §2.5）：品种清单、symbol 编码、乘数、保证金金额、组合优惠等静态参数，取自 `品种边界表.md` 权威源。

## 八、数据层（v2 草案）
- 取数单元划分（品种名单 / 边界表 / 指数日线 / 现货 / 权利金 / OI / IV / 日历 / 持仓 / 资金）须重新定义；v1 的 D01–D18 思路可借鉴但不照搬。**「预算」不是取数单元**（策略参数，入 `global_config` 的 `budget.*`，见库表设计 §2.1 / §3.6）。
- 缓存策略：`pull_date` + 预取 + 纯缓存运行（scan --offline）思路可借鉴，但须重新定义。
- **已定**：缓存落地为单一 `option.db`（表结构见库表设计）；**待定**：数据源取舍。

## 九、策略逻辑（v2 草案）
- 在阶段二就绪数据之上运行，不直接触达原始取数。
- 开仓检查框架（OI / 市况 / IV 分位 / 安全垫 / 事件 / 保证金 / 封顶 / 肥瘦 / 否决信号）须重新设计、**阈值重新校准**，不沿用旧配置。
- 结构选择（单卖 / 双卖触发、选腿、保护腿护栏）、平仓规则（止盈 / 止损 / 破位 / 到期）、仓位风控（笔数 / 每品种 / 同持品种）待细化。

## 十、输出
- 判定四态：**PASS / FAIL / WARN / MISSING**（数据不足或质检未过一律 MISSING）。
- 综合日报四块：**A 开仓机会 / B 持仓处置 / C 组合风控 / D 提醒与待人工**（D 汇总就绪登记表的缺失 / 脏 / 非终态项，源自数据就绪报告）。

## 十一、非功能需求
- 三阶段可独立调度：一 / 二定时预跑，三按需；经缓存 + 就绪登记表解耦。
- 缓存优先、tbpy 实时依赖最小化；单项取数失败只降级不崩；离线可跑（打时间戳）。
- 可观测：统一日志、数据就绪门禁与质检报告（prefetch 后缺失 / 脏 / 非终态项自动跳过并告警）；中央登记表提供各表准备看板。

## 十二、明确不做（范围外）
- 不接账户、不下单、不自动交易；不预测行情、不擅自改策略规则；不做任何裸卖。
