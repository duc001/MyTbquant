# option.sell 库表设计（v2）

> 配套 `docs/需求文档.md` §六/§七。本系统**数据驱动**，库表是地基：先定 schema，再写三阶段流水线（拉取 → 检查 → 报表）与策略逻辑。
> 设计原则：
> 1. **业务数据**与**控制面**分离（逻辑上）：二者同处一个库文件 `option.db`，但用**不同的表**区分——业务数据表（§三）与控制面表（§二）互不混写，权限 / 生命周期也不同。
> 2. **价格口径两分**（承接需求文档 §二.1）：连续指数合约日线用**后复权**，仅供相对指标；合约（期货日线）/ 期货tick（`future_tick`，即标的期货合约当前价）/ 权利金用**不复权**，供一切绝对价。混用即缺陷。
> 3. **日线类**业务表按 `bar_date`（数据日期 / 交易日）分区 / 建索引；**快照类**（如 `option_iv` / `option_quote_snapshot`，见 §三.7 / §三.6）以 `snapshot_time` 为时间维度、不另设 `bar_date`。**实时数据两分**：盘口 tick（`bid`/`ask`/`last`、live premium、live IV）属"此刻"瞬时值，仅用于盘中实时选腿 / 定价，**不写为日线类业务表的定稿行**；确需保留的实时值（如 `option_iv` 的 IV 快照）以**快照表 + `snapshot_time` 完整时点**方式落库，不与日终定稿行混淆（详见 §五）。
> 4. **命名规范**：全系统**单一库文件** `option.db`（不再一表一库）；**表名**一律**两词以上**且**与 v1 严格区分**（v1 用单词名如 `spot`/`iv`/`position`/`capital`，v2 改为 `future_tick`/`option_info`/`option_daily`/`option_quote_snapshot`/`option_iv`/`account_position`/`account_capital`/`trading_calendar`/`main_contract_daily`/`contract_daily` 等）；**"期权链"不是表名**——链是 `option_info` 的查询结果，`d06_option_chain.py` 是取数单元（见 §3.4）；字段须定义清楚（口径 / 单位 / 来源）。
> 5. **可拉尽拉**：凡是数据源能取到的字段——即使当前策略暂未使用——也**一律落库存储**，不得因"暂时不用"而丢弃（避免日后分析时无数据）。
> 6. 旧 `strategies/sell_option/` 的表结构**不沿用**，本文件为全新首稿。

## 一、存储布局

```
option/sell/data/
└── option.db   # 全系统唯一库文件
    ├─ 业务数据表（§三，9 张）
    │   ├─ main_contract_daily        连续指数合约日线（后复权）
    │   ├─ contract_daily             月度期货合约日线（不复权）
    │   ├─ future_tick                期货 tick 数据（不复权）
    │   ├─ option_info                期权合约信息（合约级·滚动，静态参考）
    │   ├─ option_daily               期权合约日线（不复权）
    │   ├─ option_quote_snapshot      期权盘口快照（盘中，按时点）
    │   ├─ option_iv                  隐含波动率（品种级时点快照）
```

## 二、控制面（库：option.db）

> 控制面 6 张表与业务数据同库（见 §一），但逻辑隔离、互不混写（设计原则 1）。其数据**非外部行情拉取**，而是由系统生成或 manual 维护，分三类职责：**配置 / 声明**（`data_storage_rule`、`全局配置表`、`future_info`）、**运行态**（`data_state_check` 状态登记 + `data_pull_detail` 拉取明细流水）、**静态参考**（`trading_calendar` 交易日历，存在即终，见 §2.6）。

### 2.1 全局配置表（KV 表）

- **用途**：系统级 KV 配置——数据源优先级与降级顺序（`source.*`）、预取时机（`schedule.*`）、门控严格度（`gate.*`）、库路径（`path.db`）等固定开关。阶段二 / 三只读消费。
- **数据源**：**manual**（手工维护 / 启动加载），非外部行情拉取。
- **抽取方法**：初始化时写入或 `UPSERT`；以 `key` 为主键，不加自增 id（见 §四）。

```sql
CREATE TABLE 全局配置表 (
    key         TEXT PRIMARY KEY,  -- 配置项名（含分组前缀，如 source.tbpy_priority / path.db）
    value       TEXT,              -- 配置值
    remark      TEXT,              -- 说明
    create_time TEXT,              -- 创建时间 YYYY-MM-DD HH:MM:SS
    update_time TEXT               -- 最后更新时间 YYYY-MM-DD HH:MM:SS
);
```
> KV 配置表以业务 `key` 为主键，**不加自增 id**（避免"重复 key"有后路）。

### 2.2 data_storage_rule（数据存储规则表）

- **用途（表名 `data_storage_rule`，中文名「数据存储规则表」）**：阶段零**声明性配置**——登记"每张业务表（取数单元）该从哪取、主源是谁、基础窗口与口径标记（`date_type` 等）"。它本身不落业务数据，是阶段一 / 二 / 三读取配置的**声明入口**。**配置与逻辑分离**：本表只提供**配置参数与分类标记**，并不承载核对规则本身；"应有条数怎么算、何时算终态、什么算正常 / 异常"这些**逻辑由检查程序依据本表的标记实现**，结果写入 `data_state_check`（见 §2.3）。本表是"声明"，检查程序是"规则引擎"。
  - **粒度**：一行 = 一个取数单元（以 `table_ref` 标识），即**一表一取数单元**（如 `main_contract_daily` 一张表、一种后复权取数方式，覆盖 `future_info` 中全部 `main_index_symbol`（活跃主连））；数据源记于 `data_source` 单列（不设降级列）。
  - **字段语义**：
    - `table_ref`：落到哪张物理表；同时充当**取数单元唯一键**，以及与 `data_state_check` 对账的连接键（`UNIQUE`）。
    - `table_name`：表名（人读，区别于 `table_ref` 的物理表引用；如 '主连后复权日线'）。
    - `date_type`：数据类型的**元数据**（Tbquant 定义名 `bar` / `tick` / `static`，不翻译）。本表仅做分类标注，**下游各规则据此施管**：bar→日线终态判定、static→存在即终、tick→无终态（tick 档含实时瞬时值与快照，如 `option_iv`；快照写模式对应 `store_mode='append_snapshot'`，`date_type` 与 `store_mode` 维度不同、不冲突）。
    - `data_source`：主数据源（如 `tbpy`）。
    - `pull_method`：拉取方式（`post_close` / `intraday` / `event` / `low_freq`；`low_freq` 用于低频/静态单元如 `trading_calendar`）。
    - `pull_count`：每次拉取的**回溯条数**，**按每标的计**（main_contract_daily=300 为整窗重拉；incremental_upsert 表仅取新 bar，`pull_count=1`；实时/static 档留空）。
    - `store_mode`：落库模式，取值各对应一档数据：`incremental_upsert`→不复权档（如 `contract_daily`）/ `full_window_rewrite`→后复权档（如 `main_contract_daily`）/ `append_snapshot`→实时快照档（如 `option_iv`）。
    - `required_fields`：必填非空字段，字段级缺失检。
    - `status`：状态（1=有效/0=无效；有效=纳入应有效验，无效=旁路不拉不校验、不报错）。
  - **三阶段驱动（配置供程序消费）**：①阶段一按本表逐行（启用态）拉取并落库；②阶段二**检查程序**据 `date_type` 等标记实现核对——bar 档"应有条数" = `[bar_start_date, bar_end_date]` 区间内**实际交易日数**（依 `trading_calendar` 剔除节假日）× `future_info` 中全部 **`main_index_symbol` 实体数**——**不得用区间自然日跨度推算**（节假日无 bar 数据）；终态与正常 / 异常判定同样由检查程序按 `date_type` 实现（语义见 §2.3 四态 / §五）；③阶段三门控据 `data_state_check` 判定放行：**仅当 `status='normal'` 且 `bar_end_date` 已覆盖到所需交易日**才放行，否则（区间未覆盖 / `init` / `fetching` / `abnormal`）阻塞或等待。
  - **与 `data_state_check` 的关系（配置面 vs 状态面）**：两表经 `table_ref` 关联。`data_storage_rule` 是**被监控表的声明**（配置面）；`data_state_check` 是**检查程序依据本表声明、对每张表核对后的逐表状态登记**（状态面）。本表不定义"应有"的推导公式，只给出声明性参数（`date_type` / `pull_count` / `future_info` 关联等），具体"应有条数 / 终态 / 正常·异常判定"由检查程序实现，结果写回 `data_state_check`（status / last_detail_id 等）；对不上的即数据异常（见 §2.3 四态）。
  - **单一声明源（非规则源）**：§三 各表"用途 / 数据源 / 抽取方法"仅为人读说明，其**声明性取值**（数据源 / 窗口 / 写模式）以本表为准，冲突优先本表；但**核对规则（应有推导、终态与正常异常判定）不在本表**，由检查程序实现（见 §2.3 / §五）。

- **数据源 / 维护**：**manual**（设计期固化），随 schema 设计写入、状态 `status`；系统启动加载为期望基线。

- **一致性约束**：各业务表须按 §四 在其上建立 `UNIQUE` 约束以保证去重（本表不另存去重键）；`store_mode` / `date_type` 取值须与对应业务表实际取数 / 存储方式一致。

```sql
CREATE TABLE data_storage_rule (
    id INTEGER PRIMARY KEY AUTOINCREMENT,            -- 自增主键
    table_ref    TEXT UNIQUE,   -- 物理表引用（取数单元唯一键 + 对账连接键）
    table_name   TEXT,          -- 表名（人读）
    date_type    TEXT,          -- 数据类型
    data_source  TEXT,          -- 主数据源
    pull_method  TEXT,          -- 拉取方式
    pull_count   INTEGER,       -- 每标的回溯条数（实时档留空）
    store_mode   TEXT,          -- 落库模式
    required_fields TEXT,       -- 必填非空字段清单（逗号分隔列名）
    status       INTEGER DEFAULT 1,  -- 状态（1=有效/0=无效）
    remark       TEXT,          -- 备注
    create_time  TEXT,          -- 创建时间
    update_time  TEXT           -- 更新时间
);
```

### 2.3 data_state_check（数据状态核对表）

- **用途（表名 `data_state_check`，中文名「数据状态核对表」）**：`data_storage_rule` 所登记各取数单元的**逐表运行状态登记**（按 `table_ref` 1:1 对账）。每行记录该表**当前已就绪的数据区间 `[bar_start_date, bar_end_date]`**、**当前状态**（`status`，四态见字段语义）与**最近一次明细引用**（`last_detail_id` → `data_pull_detail.id`）。回答"这张表的数据是否准备完毕且正确"：`normal` 放行 / `abnormal` 阻塞 + 报警 / `init`·`fetching` 等待。本身是**状态面**：只沉淀核对结论，**不存明细**——拉取日期、实拉条数、`err_msg` 等一律记入 `data_pull_detail`（见 §2.4）；核对规则由检查程序实现（见 §2.2）。
  - **字段语义**：
    - `id`：自增主键，仅标识写入先后。
    - `table_ref`：本表主键（= `data_storage_rule.table_ref`，两表经此 1:1 对账），`UNIQUE`。
    - `bar_start_date`：本状态覆盖的数据**起始交易日**（归属日 `YYYY-MM-DD`）；对 bar 档即 bar 区间起点，对 tick/static 档表示其数据覆盖的日期范围（或留空，由新鲜度 / 完整性判定，见 §五）。
    - `bar_end_date`：本状态覆盖的数据**结束交易日**（通常为最新已就绪 `bar_date`）；与 `bar_start_date` 共同标识"已核对的是哪段数据"，而非拉取动作日。
    - `status`：**四态状态机**（简化，驱动全部门控）。取值：`init`（初始化：已登记、待拉取）→ `fetching`（拉取中：含校验中、盘中形成中 bar 尚未定稿，视为"尚未准备完毕"）→ 终局之一：`normal`（数据正常：拉取完成且校验通过、终态、**可放行**）/ `abnormal`（数据异常：缺数据 / 脏数据 / 校验不通过，**阻塞 + 报警**）。门控口径：仅 `normal` 放行；`init` / `fetching` 等待；`abnormal` 阻塞。
    - `last_detail_id`：指向 `data_pull_detail.id` 的**最近一次明细引用**；检查程序每轮动作后 upsert 本表并把本次明细行 `id` 写入此列，状态表借此关联到"当前结论来自哪次拉取"，错误 / 计数等明细全部从 `data_pull_detail` 读取，本表不存 `err_msg`。
  - **与 `data_storage_rule` 的关系（状态面）**：本表给**核对结论**（status / last_detail_id 指针），`data_storage_rule` 给"声明"（被监控表 + 参数）。"应有"推导与"正常 / 异常"判定由**检查程序**按 `date_type` 实现（bar：区间内实际交易日数（`trading_calendar` 剔除节假日）× `future_info` 全部 `main_index_symbol` 实体数，勿用自然日跨度；tick：新鲜度；static：完整性），对不上的即 `abnormal`（见 §2.3 四态 / §五）；检查程序内部比对"应有 vs 实有"后只暴露结论（状态 + 明细指针，错误明细在 `data_pull_detail`），不持久化实有计数。
  - **不使用外键**：`data_state_check` ↔ `data_storage_rule` 仅以业务键 `table_ref` 软引用（1:1），`data_state_check.last_detail_id` ↔ `data_pull_detail.id` 亦为软引用；`id` 仅表写入先后、随 upsert 会变，挂外键会悬空，故两表（及对账明细）以业务键 / id 软关联、无需外键。

- **数据源 / 写入**：**系统生成（检查程序产出）**——阶段一创建行置 `init`、启动拉取置 `fetching`，阶段二（校验）完成置 `normal` / `abnormal`；异常时检查程序可重试，每次重试作为新动作行记入 `data_pull_detail`（以 `pull_time` 区分），状态表仅以 `table_ref` upsert 刷新当前态与 `last_detail_id`；每轮预取 / 校验后 upsert。

```sql
CREATE TABLE data_state_check (
    id INTEGER PRIMARY KEY AUTOINCREMENT,   -- 自增主键
    table_ref TEXT UNIQUE,                  -- 本表主键（= data_storage_rule.table_ref，1:1 对账）
    bar_start_date TEXT,                    -- 覆盖的数据起始交易日
    bar_end_date TEXT,                      -- 覆盖的数据结束交易日（最新已就绪 bar_date）
    status    TEXT,                         -- 四态状态机：init→fetching→(normal|abnormal)；仅 normal 放行
    last_detail_id INTEGER,                 -- 最近一次明细引用（→ data_pull_detail.id）
    remark TEXT,                            -- 备注
    create_time TEXT, update_time TEXT,     -- 创建/更新时间
);
```

### 2.4 data_pull_detail（数据拉取明细表）

- **用途（表名 `data_pull_detail`，中文名「数据拉取明细表」）**：每次拉取 / 核对动作的**流水明细**，与 `data_state_check`（状态登记，每表一行）互补。后者只存"当前状态"，本表存"每次动作发生了什么"——拉取日期 (`pull_date`)、覆盖的数据区间、应有 / 实有计数、明细错误、拉取时间 (`pull_time`)。它是 `data_state_check` 的**审计轨迹**：某张表今天拉了几次、每次拉到多少、为何失败，全在本表可追溯；状态表只沉淀最终结论。
  - **粒度**：一行 = 一次拉取 / 核对动作（`table_ref` + `pull_time` 唯一确定）；同一 `table_ref` 可有多行（每日多次拉取 / 重试均留痕）。
  - **字段语义**：
    - `id`：自增主键。
    - `table_ref`：连接键（= `data_storage_rule.table_ref`），与状态表对账。
    - `pull_date`：**拉取日期**（`YYYY-MM-DD`，本次拉取动作发生的日期，动作日）——区别于业务表数据归属日 `bar_date`，也区别于状态表的数据就绪区间。
    - `pull_time`：本次拉取**完整时间戳**（`YYYY-MM-DD HH:MM:SS`，动作时刻）；`pull_date` 为其日期部分，本列用于排序 / 定位每次拉取动作，取代原 `fetch_at` / `validate_at` 的"动作时间"角色。
    - `bar_start_date` / `bar_end_date`：本次拉取覆盖的数据区间（对 bar 档即 bar 区间；对 tick/static 档表示其数据覆盖的日期范围，或留空由新鲜度 / 完整性判定，见 §五）。
    - `expected_n`：检查程序推导的**应有条数**（审计用）；算法：区间内**实际交易日数**（依 `trading_calendar.is_trading_day=1` 剔除节假日）× 活跃实体数，**不得用 `[bar_start_date,bar_end_date]` 自然日跨度推算**（节假日无 bar 数据）。
    - `actual_n`：本次**实拉条数**。
    - `status`：本次动作结果的**状态快照**（init / fetching / normal / abnormal），与状态表 `status` 同域。
    - `err_msg`：本次**明细错误的摘要**（缺失字段类别 / 异常品种计数 + 少量样本 / 失败原因）；**硬约束：不得逐条罗列全部异常项**——异常品种 / 行等列表过长时仅保留前若干样本并附"…共 M 条"计数，保持单行轻量、可消费；逐条排查由业务表反查，不塞入本字段。
    - `remark`：备注。
    - `create_time` / `update_time`：创建 / 更新时间。
  - **与 `data_state_check` 关系（流水 vs 状态）**：状态表（§2.3）每表一行沉淀"当前是否 ready"，本表每表多次一行留痕（粒度见上）。检查程序每轮拉取 / 校验后**双写**：既 upsert 状态表（`table_ref` 行，刷新 `status` / 数据区间 / `last_detail_id`），也 insert 本表（新动作行，以 `pull_time` 唯一区分）。

- **数据源 / 写入**：**系统生成（检查程序产出）**——每轮拉取 / 校验动作完成（或失败）后 insert 一行。

```sql
CREATE TABLE data_pull_detail (
    id INTEGER PRIMARY KEY AUTOINCREMENT,   -- 自增主键
    table_ref TEXT,                         -- 连接键（= data_storage_rule.table_ref）
    pull_date TEXT,                         -- 拉取日期（动作发生日，非 bar 归属日 bar_date）
    pull_time TEXT,                         -- 拉取完整时间戳（YYYY-MM-DD HH:MM:SS，动作时刻）
    bar_start_date TEXT,                    -- 本次覆盖数据起始交易日
    bar_end_date TEXT,                      -- 本次覆盖数据结束交易日
    expected_n INTEGER,                     -- 应有条数（按交易日历剔除节假日后 × 活跃实体数，审计用）
    actual_n INTEGER,                       -- 实拉条数
    status    TEXT,                         -- 本次动作结果状态快照（init/fetching/normal/abnormal）
    err_msg     TEXT,                       -- 本次明细错误（摘要化，截断勿逐条罗列）
    remark TEXT,                            -- 备注
    create_time TEXT, update_time TEXT,     -- 创建/更新时间
    UNIQUE (table_ref, pull_time)           -- 防同批次重复 upsert
);
```

### 2.5 future_info（期货品种信息表）

- **用途**：**期货品种级**静态参数——品种中文名 / 交易所 / 现价 / 乘数 / 保证金金额（单腿 / 实际占用）/ 组合优惠，以及期货·期权 C/P 的 **symbol 格式模板**（`fut_symbol_template` / `opt_call_template` / `opt_put_template`，取数拼接合约用）+ 主力指数**合约**（`main_index_symbol`，后复权主连，直接拉日线）；业务表经 `product_cd` 关联 `future_info.product_cd` 取数；单列不塞进 `全局配置表`。

- **数据源**：`品种边界表.md`（本仓库内 markdown 权威源，47 品种；见 §二 开头职责划分）。本表即该文件的**结构化镜像**——取数加载器解析其【一、边界表数据】表格逐行填充，**字段严格对齐文件列**（见下），非手工维护、非外部接口；旧 `config.py` 已删，取数以本文件为准。
- **抽取方法**：初始化写入 / 维护；以 `product_cd` 为主键，不加自增 id。

### 3.1 指数合约日线：main_contract_daily

- **用途**：**主连连续合约后复权日线**（文档中常称"指数"，888 后缀，如 `m9888.DCE` / `rb888.SHFE` / `IF888.CFFEX`），服务端 `RolloverBackWard` 换月后复权、抹平主力换月跳空。**仅服务相对指标**（收益率 / 波动率 / 趋势 / ADX / 区间位置），绝不用于任何绝对价（价格口径两分铁律，见一、设计原则 2 / 需求文档 §二.1）。
- **数据源**：
  - **主源（唯一已实现）**：`tbpy`——`tbpy.get_history_n(symbol, "1d", count, fields, flag=tbpy.QuoteFlag.RolloverBackWard)` 取**服务端后复权**日线，属**三阶段驱动**的「拉取」阶段（拉取 → 检查 → 生成报表，由 §2.2 `data_storage_rule` 驱动）。
  - **返回字段**（tbpy 对连续合约返回 `time`/`open`/`high`/`low`/`close`/`volume`/`position`/`rollover` 八项）：本表**全取**——`time`（datetime）→ 格式化为 `bar_date`(`YYYY-MM-DD`)；`open`/`high`/`low`/`close`（后复权）→ 对应列；`volume`（手）→ `volume`；`position`（持仓量，手）→ `position`；`rollover`（后复权调整因子）→ `rollover`。`pre_close`/`amount`（非 tbpy 字段、对相对指标无用）与 `turnover`（换手率）/`vwap`（均价，股票口径）**已从本表移除**。
  - **为何只取后复权**：`QuoteFlag` 仅 `RolloverBackWard` 一个复权枚举、无独立「原始价」flag（原始价须 `flag=None` 另拉、且本表不需要），故一次拉取即够；原始价由 `contract_daily` 不复权表承载。
  - **备选**：**新浪**（§七 Q1 开放项，待验证）。
- **字段语义**（参考 §2.2 `data_storage_rule` 字段语义格式）：
  - `id`：自增主键，仅标识数据写入先后（技术键，非业务键）。
  - `main_symbol`：主连连续合约代码，本表业务键；对应 `future_info` 全部 `main_index_symbol`；落库以该键 `full_window_rewrite` 整段全量重写。
  - `bar_date`：交易日，`YYYY-MM-DD`。
  - `open` / `high` / `low` / `close`：后复权 OHLC（换月后复权）。
  - `volume`：成交量（手）。
  - `position`：持仓量（手，主连对应前月合约的未平仓合约数；期货持仓量信号，非相对指标必需、按需使用）。
  - `rollover`：后复权调整因子（换月系数）；本批拉取窗口内恒定、发生换月时跳变，用于复权血缘与换月观测，相对指标计算不依赖。
  - 约束：`UNIQUE(main_symbol, bar_date)`，同标的同交易日唯一，防意外重复插入。
  - **抽取方法**：阶段一每日盘后据 `data_storage_rule`（`table_ref='main_contract_daily'`）预取 → `get_history_n(..., count=pull_count, fields, flag=RolloverBackWard)` 拉后复权 OHLC + 持仓量/复权因子。`pull_count` 默认 **300**（≈1.2 年日线，覆盖 ADX / 波动率 / 区间百分位回看）。**落库 = `store_mode='full_window_rewrite'`**：整窗拉取（非仅拉新 bar），事务内先 DELETE 该标的历史窗口、再 INSERT 本批全窗，幂等、同日重拉命中缓存跳过；后复权须单锚一致，增量 append 会混新旧锚、换月后相对指标算错（机理见 §五 复权锚定）。`date_type='bar'` 派生「收盘后为终态」。对照：不复权表 `contract_daily` / `option_daily` 用 `store_mode='incremental_upsert'` 追加新 bar；`future_tick` 是**单值 tick 快照、非 bar 序列**，按 `(symbol, pull_date)` UPSERT，见 §3.3。后复权表不可增量、须整窗重写。

```sql
CREATE TABLE main_contract_daily (
    id INTEGER PRIMARY KEY AUTOINCREMENT,            -- 自增主键，标识数据写入先后
    main_symbol   TEXT,          -- 主连连续合约代码，如 m9888.DCE / rb888.SHFE / IF888.CFFEX
    bar_date   TEXT,          -- 交易日 YYYY-MM-DD
    open         REAL,          -- 开盘价（后复权，换月后复权）
    high         REAL,          -- 最高价（后复权）
    low          REAL,          -- 最低价（后复权）
    close        REAL,          -- 收盘价（后复权）
    volume       REAL,          -- 成交量（手）
    position     REAL,          -- 持仓量（手）
    rollover     REAL,          -- 后复权调整因子（换月系数）
    UNIQUE (main_symbol, bar_date)
);
```

- **录入示例**（`store_mode='full_window_rewrite'`，事务内整窗重写，幂等）：
  ```python
  def store_main_contract_daily(conn, symbol, bars):
      # bars: get_history_n 返回、并经 time(datetime)→bar_date(YYYY-MM-DD) 格式化的全窗行
      with conn:  # 单事务：先删该标的历史窗口，再插本批全窗
          conn.execute("DELETE FROM main_contract_daily WHERE main_symbol = ?", (symbol,))
          conn.executemany(
              "INSERT INTO main_contract_daily "
              "(main_symbol, bar_date, open, high, low, close, volume, position, rollover) "
              "VALUES (:main_symbol, :bar_date, :open, :high, :low, :close, :volume, :position, :rollover)",
              bars,
          )
  # 同日重拉：DELETE 已清空该标的历史窗口后 INSERT 本批全窗 → 结果一致（幂等）
  ```
  单条样例（`m9888.DCE` 2026-09-22，取自 tbpy 实测）：
  ```sql
  INSERT INTO main_contract_daily
    (main_symbol, bar_date, open, high, low, close, volume, position, rollover)
  VALUES
    ('m9888.DCE', '2026-09-22', 14681.53989523, 14793.8435249, 14664.26241374, 14754.96919155, 1320817, 2703569, 4.31937037);
  ```

### 3.2 合约日线：contract_daily

- **用途**：**月度期货合约日线（不复权）**。承载**标的绝对价**需求——现价、行权价、保证金、安全垫、封顶、肥瘦判定；**权利金（期权自身价格）存于 `option_daily`，本表提供其估值所需的标的期货价**；与 `main_contract_daily`（后复权、相对指标）严格分流，混用即缺陷（价格口径两分铁律）。
- **数据源**：
  - **主源（唯一已实现）**：`tbpy`——`get_history_n(symbol, "1d", count, flag=QuoteFlag.Null)` 取**具体合约**的**不复权（原始）**日线，`symbol` 为月合约代码（如 `m2601.DCE`）；属「拉取 → 检查 → 生成报表」三阶段驱动的「拉取」阶段（由 §2.2 `data_storage_rule` 驱动）。
  - **返回字段**（tbpy 对具体合约必返 `time`/`open`/`high`/`low`/`close`/`volume`；`position`（持仓量）、`pre_close`/`settle`/`amount` 等视合约状态返回，标 `[可拉尽拉]`）：本表存 `symbol` + 派生 `product_cd`/`expire` + `bar_date`(←`time`，datetime 格式化为 `YYYY-MM-DD`) + 核心 OHLCV + `oi`(←`position`，持仓量) + [可拉尽拉]`pre_close`/`settle`/`amount`。
  - **为何不复权（flag=None）**：本表服务绝对价，须是真实成交原始价，故 `flag=QuoteFlag.Null`（无复权）；相对指标一侧由 `main_contract_daily`（`RolloverBackWard` 后复权）承载，两表字段口径不可混。
  - **备选**：**新浪(sina)**（§七 Q1 开放项，待验证）。
- **字段语义**（参考 §2.2 `data_storage_rule` 字段语义格式）：
  - `id`：自增主键，仅标识数据写入先后（技术键，非业务键）。
  - `symbol`：月合约代码（如 `m2601.DCE`），本表业务键；对应 `future_info` 全部合约。
  - `product_cd`：标的代码，由 `symbol` 解析派生（合约代码含标的与到期月）。
  - `expire`：到期月 `YYYY-MM`，由 `symbol` 解析派生。
  - `bar_date`：交易日，`YYYY-MM-DD`。
  - `open` / `high` / `low` / `close`：不复权 OHLC（真实成交价）。
  - `pre_close`：昨收 [可拉尽拉]。
  - `settle`：结算价 [可拉尽拉]（期货保证金计算依赖）。
  - `volume`：成交量（手）。
  - `amount`：成交额（元）[可拉尽拉]。
  - `oi`：持仓量（手，← tbpy `position` 字段）。
  - 约束：`UNIQUE(symbol, bar_date)`，同合约同交易日唯一，防意外重复插入。
  - **抽取方法**：阶段一每日盘后据 `data_storage_rule`（`table_ref='contract_daily'`）预取 → `get_history_n(symbol, "1d", count=pull_count, flag=QuoteFlag.Null, fields=fields)` 拉不复权日线。`store_mode='incremental_upsert'`：**仅拉新 bar**（`pull_count=1`，见 §2.2），`UPSERT` 追加/更新该合约当日行、不回写历史；`date_type='bar'` 派生「收盘后为终态」（盘中 `bar_date==today` 行为临时值）。对照：`main_contract_daily` 用 `full_window_rewrite` 整窗重写、不可增量。

```sql
CREATE TABLE contract_daily (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol       TEXT,          -- 月合约代码，如 m2601.DCE
    product_cd   TEXT,          -- 标的代码（由 symbol 解析派生）
    expire       TEXT,          -- 到期月 YYYY-MM（由 symbol 解析派生）
    bar_date     TEXT,          -- 交易日 YYYY-MM-DD
    open         REAL,          -- 开盘价（不复权）
    high         REAL,          -- 最高价（不复权）
    low          REAL,          -- 最低价（不复权）
    close        REAL,          -- 收盘价（不复权）
    pre_close    REAL,          -- 昨收 [可拉尽拉]
    settle       REAL,          -- 结算价 [可拉尽拉]
    volume       REAL,          -- 成交量（手）
    amount       REAL,          -- 成交额（元）[可拉尽拉]
    oi           REAL,          -- 持仓量（手，← tbpy position）
    UNIQUE (symbol, bar_date)
);
```

- **录入示例**（`store_mode='incremental_upsert'`，仅追加/更新新 bar，幂等）：
  ```python
  def store_contract_daily(conn, symbol, bars):
      # bars: get_history_n(flag=QuoteFlag.Null) 返回、并经 time(datetime)→bar_date(YYYY-MM-DD) 格式化的行
      conn.executemany(
          """INSERT INTO contract_daily
             (symbol, product_cd, expire, bar_date, open, high, low, close, pre_close, settle, volume, amount, oi)
             VALUES (:symbol, :product_cd, :expire, :bar_date, :open, :high, :low, :close, :pre_close, :settle, :volume, :amount, :oi)
             ON CONFLICT(symbol, bar_date) DO UPDATE SET
                open=excluded.open, high=excluded.high, low=excluded.low, close=excluded.close,
                pre_close=excluded.pre_close, settle=excluded.settle, volume=excluded.volume,
                amount=excluded.amount, oi=excluded.oi""",
          bars,
      )
  # 同日重拉：ON CONFLICT 命中 UNIQUE(symbol, bar_date) → 更新而非重复插入（幂等）
  ```
  单条样例（`m2611.DCE` 2026-09-22，取自 tbpy 实测，数值为示意）：
  ```sql
  INSERT INTO contract_daily
    (symbol, product_cd, expire, bar_date, open, high, low, close, pre_close, settle, volume, amount, oi)
  VALUES
    ('m2611.DCE', 'm', '2026-11', '2026-09-22',
     3520.00, 3535.00, 3508.00, 3528.00,        -- 不复权 OHLC
  ```

### 3.3 期货tick数据：future_tick

> 对应代码取数器 `d08_spot_price`（其 `symbol` 即 `futures_symbol`）。

- **用途**：**标的期货合约的盘中 tick 价**——期权决策的**盘中绝对价基准**：
  - 选行权价档位：`select_legs` 以现价锚定短腿 / 保护腿；
  - #5 **安全垫**：现价 → 保护腿缓冲；
  - §7.3 **破位**对照价；
  - **保证金**估算（`estimate_candidate_margin(selection.spot, …)`，不依赖期权盘口）。
  - 盘后 / 休市现价**不由本表提供**，读 `contract_daily` 最新 bar 的 `close`。
- **数据源**：
  - **主源（唯一源）**：`tbpy`——`get_current_tick(symbol=[...])`（盘中实时 tick）。**只此一路，不取日线**。
    - **必须传 list**（实测）：传单个字符串 `symbol="m2611.DCE"` → **返回 `None` 且不报错**；传 list 才返回 `list[Tick]`。
    - **限流**（实测）：实时查询同样是 **1 次 / 60s**、单次 **≤20 合约**；超限报 `查询实时失败,查询限制,间隔=60000ms,合约数量=20`。故按 ≤20/批 + 批间 60s 拉取。
    - `futures_symbol` 由 D06/D07 候选标的月给出（如 `m2611.DCE`），**只取真实合约、永不碰 888/9888 指数**（串价铁律）。
  - **返回字段**（返回 `tbpy.Tick`；类定义字段 **14** 个——`symbol` / `time` / `open` / `high` / `low` / `last`（最新价）/ `limit_up` / `limit_down` / `volume` / `total_volume` / `avg_price` / `pre_close` / `pre_settlement` / `bidasks`（盘口列表，元素 `BidAsk`：`bid_p`/`bid_v`/`ask_p`/`ask_v`）；**Tick 无持仓量字段**——持仓量是 `Bar.open_int`）：本表**只取 `last`（→`price`）与 `time`（→`snapshot_time`）**；其余字段本策略不用、不落库。
  - **实测结果**（`au2612.SHFE` 夜盘 2026-10-14；每次调用均间隔 65s 以避开 60s 限流）：
    ```
    ① 01:16:44.500000   get_quote([...])                 last=899.56
       bidasks（5 档，bid_p×bid_v / ask_p×ask_v）:
         (899.54×8 / 899.60×5)  (899.48×6 / 899.62×1)  (899.46×1 / 899.68×1)
         (899.44×2 / 899.70×1)  (899.40×2 / 899.72×2)
    ② 01:17:49.500000   get_current_tick(symbol=[...])   last=899.46
       bidasks（5 档）: (899.44×1 / 899.48×4) (899.42×3 / 899.50×3) (899.40×3 / 899.52×2)
                        (899.38×3 / 899.56×2) (899.36×5 / 899.58×1)
    ③ 01:51:41.500000   tick_batch(['au2612.SHFE'])      last=898.20
       → {'au2612.SHFE': {'last': 898.2,
                          'bar_date': 2026-10-14,
                          'snapshot_time': 2026-10-14 01:51:41.500000}}
    ```
    - 三次 `last` 持续变化（899.56 → 899.46 → 898.20）且 `time` 带毫秒 ⇒ 确为**实时 tick**；盘口返回 **5 档** `BidAsk`。本次仅取值 `symbol`/`last`/`time`/`bidasks`，其余字段值待补。
    - ③ 走的是**修复后的 D08 取数器**（`tick_batch`，list 传参）：改前 `tick()` 传字符串恒返回 `None`，改后返回真值 —— **list 传参修复验证有效**。
    - ③ 之后紧接着再调一次 `tick()` 返回 `None`：两次调用间隔 <60s 命中限流，属**预期行为**，非故障。
  - **盘后 / 非交易时段**：返回 `None` → **不取数、不落行**；现价读 `contract_daily` 最新 bar 的 `close`（同一 `futures_symbol` 已存该值，不重复取数、不重复存储）。
- **字段语义**（盘中 tick 快照，键 `(symbol, pull_date)`）：
  - `symbol`：真实期货合约代码（`futures_symbol`，如 `m2611.DCE`），业务键。
  - `pull_date`：取数归属交易日 `YYYY-MM-DD`（D15 日历得出，查询键）。tick 恒为当日，故不另设 `bar_date`。
  - `price`：tick 价（绝对价）；`NULL` 即该合约 **MISSING**（绝不拿指数 / 代理价冒充，§八 四态原则）。
  - `snapshot_time`：该 tick 的真实时刻（← `Tick.time`，`YYYY-MM-DD HH:MM:SS.sss`）。**夜盘跨自然日**时其自然日可早于 `pull_date`（如 10-13 22:00 的 tick 记 `pull_date=10-14`）；同一交易日多次取数按 `UNIQUE(symbol, pull_date)` 覆盖，靠本字段追溯所存的是哪一刻。
  - `source`：`tick`（命中）/ `none`（无 tick）。
  - 约束：`UNIQUE(symbol, pull_date)`，同合约同交易日唯一。
  - **抽取方法**：阶段一**盘中**据 `data_storage_rule`（`table_ref='future_tick'`）触发 D08 `fetch_d08`，走 `get_current_tick` 取各候选合约 tick、组装 `SpotSet`；盘后不触发。本表是**tick 快照、非 bar 序列**，无 `date_type='bar'` 终态语义；按 `(symbol, pull_date)` UPSERT。

```sql
CREATE TABLE future_tick (
    symbol         TEXT,          -- 真实期货合约代码（futures_symbol，如 m2611.DCE）
    pull_date      TEXT,          -- 取数归属交易日 YYYY-MM-DD（查询键）
    price          REAL,          -- 盘中 tick 价（绝对价）；NULL=MISSING
    snapshot_time  TEXT,          -- tick.time：YYYY-MM-DD HH:MM:SS.sss（该 tick 真实时刻）
    source         TEXT,          -- tick / none
    UNIQUE (symbol, pull_date)
);
```

- **录入示例**（盘中 tick UPSERT，幂等）：
  ```python
  def store_future_tick(conn, symbol, pull_date, price, snapshot_time, source):
      conn.execute(
          """INSERT INTO future_tick (symbol, pull_date, price, snapshot_time, source)
             VALUES (?, ?, ?, ?, ?)
             ON CONFLICT(symbol, pull_date) DO UPDATE SET
                price=excluded.price, snapshot_time=excluded.snapshot_time,
                source=excluded.source""",
          (symbol, pull_date, price, snapshot_time, source))
  ```
  单条样例（`au2612.SHFE` 夜盘实测 2026-10-14 01:16:44）：
  ```sql
  INSERT INTO future_tick
    (symbol, pull_date, price, snapshot_time, source)
  VALUES
    ('au2612.SHFE', '2026-10-14', 899.56, '2026-10-14 01:16:44.500000', 'tick');
  ```

### 3.4 期权合约信息：option_info

> **实现状态**：期权侧三表（`option_info` / `option_daily` / `option_quote_snapshot`）**目前仅设计、代码未落地**
> （全库无 `CREATE TABLE` / `INSERT` / `SELECT`）；期权侧现落库的是旧缓存表 `premium`、`iv_snapshot`，落地时收编。

- **用途**：**期权合约清单 / 条款**（`symbol` 级静态参考表）。回答"现在有哪些期权合约、各自什么条款"——
  选腿枚举行权价档位、DTE 计算、symbol 解析校验皆以此表为准。
- **为何不并入 `future_info`（§2.5）**：`future_info` 是**品种级、固定**（47 行），期货合约可由模板 + 月份推导；
  期权**行权价阶梯不可推导、且逐月滚动**（m 当前 8 个标的月 / 310 合约）→ 必须**合约级 + 滚动维护**。
- **"期权链"不是表**：链＝`WHERE product_cd=? AND underlying_month=?` 查出的一批行（行权价 × C/P），
  是**查询结果**；`d06_option_chain.py` 是产出本表的**取数单元**。
- **数据源**：主源 **tbpy**——`get_symbols()` 过滤出期权 symbol + `get_instrument(symbol=…)` 补元数据。
  （工程注意：`get_symbols()` 返回约 **11.4 万**条，须在**隔离子进程 / 模块级持有**以避免析构时堆损坏。）
  备源 **openvlab** `/api/product-exps`（仅到期日）、**新浪**（仅主力月阶梯）**都不能独立建链**；
  全源失败 → 该品种断源、下游判 **MISSING**，不猜合约。
- **抽取方法**：日频增量——`get_symbols()` 比对新增 symbol → 逐个 `get_instrument()` 写入；
  `delisted_date` 已过即失效（**滚动闭环**）。`symbol` 为 `PRIMARY KEY`，**静态表不加自增 id**（§四）。

- **返回字段（`get_instrument` → `Instrument`，实测全量 10 个；样例 `m2611-C-3000.DCE`）**：

  | # | 返回字段 | 类型 / 实测值 | 落库 | 说明 |
  |---|---|---|---|---|
  | 1 | `symbol` | `str` `m2611-C-3000.DCE` | → `symbol`（PK） | 完整合约代码 |
  | 2 | `sec_id` | `str` `m2611-C-3000` | **不落** | ＝`symbol` 去交易所后缀，冗余 |
  | 3 | `sec_name` | `str` `豆粕期权m2611-C-3000` | → `sec_name` | 合约中文名（唯一人工可读字段） |
  | 4 | `exchange` | `str` `DCE` | **不落** | ＝`symbol` 后缀，且＝`future_info.exchange` |
  | 5 | `listed_date` | `datetime` `2025-11-17 00:00:00` | → `listed_date` | 格式化为 `YYYY-MM-DD`；识别新挂合约 |
  | 6 | `delisted_date` | `datetime` `2026-10-23 00:00:00` | → `delisted_date` | 期权最后交易日＝**DTE 基准**；过期即失效 |
  | 7 | `price_tick` | `float` `0.5` | → `price_tick` | **期权 ≠ 标的期货**（m 1.0/0.5、i 0.5/0.1），必须本表存 |
  | 8 | `contract_unit` | `float` `10` | **不落** | 实测与标的期货一致 → 取 `future_info.multiplier`（单一事实来源） |
  | 9 | `big_point_value` | `float` `1.0` | **不落** | 7/7 样本恒为 1.0，零信息量（金额＝价 × 1 × `contract_unit`） |
  | 10 | `deal_times` | `str` `'\|21:00-23:00;09:00-10:15;10:30-11:30;13:30-15:00;\|\|\|\|\|'` | → `deal_times` | 交易时段串（`\|` 起、`;` 分 8 段：夜盘 + 3 段日盘 + 4 空段）；**`session_hours` 交叉校验源**（见下） |

  - `get_symbols()` **只返回 `list[str]`**（仅 symbol 字符串，无任何元数据）→ 元数据只能逐合约
    `get_instrument()` 补齐。
  - `product_cd` / `underlying_symbol` / `underlying_month` / `cp` / `strike` **不是接口返回字段**，
    由 `symbol` 解析得出（格式随交易所而异，见结论 4）→ 解析一次落库，下游不再各自解析。
  - **`deal_times` 的真实价值**：与本地 `session_hours` 对照发现分歧且 **tbpy 更准**——
    SHFE `cu` 本地 21:00-**02:30** vs tbpy 21:00-**01:00**（铜实际收 01:00，au/ag 才是 02:30）；
    CZCE 本地 21:00-**23:30** vs tbpy 21:00-**23:00**（郑商实际收 23:00）。
    故保留该列作**自动对账源**，而非"已本地化故丢弃"。

- **实测核对**（`get_instrument`，2026-10-15 / 10-16）：

  | symbol | 类型 | `delisted_date` | `contract_unit` | `price_tick` |
  |---|---|---|---|---|
  | `m2611.DCE` | 期货 | 2026-11-13 | 10 | 1.0 |
  | `m2611-C-3000.DCE` | 期权 | **2026-10-23** | 10 | **0.5** |
  | `i2611.DCE` | 期货 | 2026-11-13 | 100 | 0.5 |
  | `i2611-C-800.DCE` | 期权 | **2026-10-23** | 100 | **0.1** |

  1. **期权 `delisted_date` ≠ 标的期货**（m2611：10-23 vs 11-13，早 21 天）→ 必须**合约级自存**，
     不可由标的月反推（`x4_expiry` 的 DTE 基准）。
  2. **`price_tick` 期权 ≠ 标的期货**（m 1.0/0.5、i 0.5/0.1）→ **必须本表存**，不能取 `future_info`。
  3. **`contract_unit` 与标的期货一致**（10/10、100/100、5/5）→ 单一事实来源在 `future_info.multiplier`，
     **本表不存**（避免两处维护）。
  4. **symbol 格式随交易所而异**：DCE `m2611-C-3000`、SHFE `cu2611C80000`、CZCE `CF701C15000`

     **解析后落库**，下游不再各自解析。
  5. **行权价阶梯不可推导**（故需实测取回）：m2611 实测 2500…3800 共 **26 档**（C/P 各 26），且**档距分段**
     （2500→2600 为 100、2600 起为 50）→ 无法按固定档距推算，只能来自 `get_symbols()`。

```sql
CREATE TABLE option_info (              -- 静态参考表：业务键为 PRIMARY KEY，不加自增 id（§四）
```

### 3.5 期权合约日线：option_daily

- **用途**：**逐期权合约的不复权日线真值**（权利金 + 成交 + 持仓）。选腿（#5 安全垫、#7/#8 封顶、#9 肥瘦）
  以本表 `close` / `oi` 为输入；**只存数据源真值，不存派生量**（派生列已清理，见下）。
- **数据源**：主源 **tbpy** `get_history_n(symbol=[...], frequency='1d', count=1, fields=[...])`
  （限流 1 次 / 60s，symbol 传 **list** 可一次带 ≤20 合约算 1 次查询 → **≤20/批 + 批间 62s 冷却**；
  与 D09/D10 同款）。盘后口径主值＝`close`。

- **返回字段（`get_history_n` → 按 `fields` 名返回 `{symbol: {field: [值]}}`，实测 2026-10-16 00:17）**：

  | `fields` 名 | 类型 / 实测值（`m2611-P-3000.DCE`） | 落库 | 说明 |
  |---|---|---|---|
  | `open` | `float[]` `[0.5]` | → `open` | 开盘 |
  | `high` | `float[]` `[0.5]` | → `high` | 最高 |
  | `low` | `float[]` `[0.5]` | → `low` | 最低 |
  | `close` | `float[]` `[0.5]` | → `close` | 收盘＝**权利金主值**（不复权） |
  | `volume` | `float[]` `[568]` | → `volume` | 成交量（手） |
  | `position` | `float[]` `[14440]` | → `oi` | **持仓量**（即 `Bar.open_int`；`fields` 里叫 `position`） |
  | `time` | `datetime[]` `[2026-10-16 00:00]` | → `bar_date` | 该 bar 的交易日，转 `YYYY-MM-DD`；**陈旧判定键** |
  | `turn_over` | **实测空数组 `[]`** | **不落** | 成交额**取不到**（3/3 样本皆空）→ 不设 `amount` 列 |
  | `rollover` | `float[]` `[1.0]` | **不落** | 复权因子；本表不复权，恒 1.0 无意义 |
  | `frequency` / `symbol` | **实测空数组 `[]`** | **不落** | 接口不填充 |

- **实测真值**：
  1. **新鲜 bar 样例**（`get_history_n` 全字段，2026-10-16 00:17 取）：
     ```
     m2611-P-3000.DCE : open=0.5  high=0.5  low=0.5  close=0.5  volume=568  oi=14440  bar_date=2026-10-16
     m2611-C-3000.DCE : open=296  high=296  low=279  close=279  volume=15   oi=1547   bar_date=2026-10-15
     m2611.DCE（期货）: open=3289 high=3291 low=3276 close=3278 volume=26256 oi=364376 bar_date=2026-10-16
     ```
     同一时刻、同一标的月：`P-3000` 已有 10-16 的 bar、`C-3000` 仍停在 **10-15** → 再一次印证
     **bar 日期必须逐合约判定**，不能按"取数日"统一认为新鲜。
  2. **陈年 bar 样例**（2026-10-15 22:28 `close_batch`）：
     ```
     m2611-C-2500 close=694.0 bar_date=2026-08-18   m2611-C-2600 close=744.5 bar_date=2026-09-15
     m2611-C-2650 close=656.0 bar_date=2026-09-29   m2611-C-2700 close=442.0 bar_date=2026-07-28
     m2611-C-2750 close=609.0 bar_date=2026-09-09
     ```
     深度实值 / 无成交合约最后一根 bar 距取数日 **17–79 天** → `close` **必须与 `bar_date` 同落**，
     下游判 `bar_date == 目标交易日`，否则把几十天前的收盘价当今日权利金（#7/#8/#9 全错）。
     这是 `UNIQUE(symbol, bar_date)` + **"陈旧即 MISSING"** 的实测依据。
- **已删除的列（不落本表）**：`iv` / `delta` / `gamma` / `vega` / `theta` / `rho` /
  `theo_price` / `margin` / `status` / `settle`（2026-10-15 清理）＋ `amount` / `pre_settle`（2026-10-16 复核追加）。
  依据＝**取不到 + 当前无消费者**（全代码检索 `checks/`：
  仅 `oi` 被 `c2_oi` 消费，greeks / theo_price / status / 合约级 iv 零命中）：
  - **tbpy 取不到**：`Instrument`(10) / `Tick`(14) / `Bar`(11) 全量实测**均无 iv、无 greeks、无保证金率、
    无结算价**；顶层 API 也无对应接口。
  - **外部源也取不到**：openvlab `/api/ctamap-all` 只有**品种级主力月** `atmv` / `skew` / `rv22`（归 §3.7
    `option_iv`）；新浪 `OptionService.getOptionData` 只给主力月 T 型盘口（代码仅取行权价阶梯）。
  - **`amount` 取不到**：`get_history_n` 的 `turn_over` 实测 **3/3 返回空数组**（成交额无源）。
  - **`pre_settle` 日线口径无源**：昨结算只在盘中 `Tick.pre_settlement` 有值 → 归 §3.6
    `option_quote_snapshot`，本表不设恒 NULL 列。
  - **`margin` 随现价变、落库即过期**：#7 走 `c7_margin.estimate_candidate_margin()` **现算**
    （现价 × 乘数(D11) × 保证金率(D04) × 组合优惠(D05)），不读表；账户真实占用在
    `Position.l/s_use_margin_amount`（账户侧）。
  - 将来若要反解合约级 IV / greeks：**另建派生表并带 `model` 标记**（Black-76 / CRR / BAW + 输入快照），
    不混进本表"真值"语义——避免阶段二把模型值当行情真值做硬判定。
- **抽取方法**：阶段一盘后按标的拉全链 → 逐合约 `UNIQUE(symbol, bar_date)` 真 upsert（增量追加新 bar）。
  **盘中拉到的行属"形成中 bar"**（`bar_date`=当日、`close` 非定稿）：按 §五 规则，下游指标计算排除、
  收盘后 `use_cache=False` 强制重拉回填。
- **字段语义**：`bar_date`＝该行价格所属交易日（**陈旧判定键，不是取数日**）；价格一律**不复权**；
  `NULL` 即 MISSING（§八 四态原则）。

```sql
CREATE TABLE option_daily (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol         TEXT,  -- 期权合约代码（→ option_info.symbol）如 m2611-C-3000.DCE
    product_cd     TEXT,  -- 标的品种码（→ future_info.product_cd），便于按品种整链扫描
    bar_date       TEXT,  -- 该行价格所属交易日 YYYY-MM-DD ← fields.time（陈旧判定键）
    open           REAL,  -- 开盘 ← fields.open [可拉尽拉]
    high           REAL,  -- 最高 ← fields.high [可拉尽拉]
    low            REAL,  -- 最低 ← fields.low [可拉尽拉]
    close          REAL,  -- 收盘价（不复权）← fields.close，权利金主值
    volume         REAL,  -- 成交量（手）← fields.volume
    oi             REAL,  -- 持仓量（手）← fields.position（即 Bar.open_int；Tick 无此字段）
    UNIQUE (symbol, bar_date)
    -- 不落：turn_over(成交额，实测空数组) / rollover(复权因子，恒 1.0) / frequency·symbol(接口不填充)
    -- 不落：pre_settle(昨结算，日线口径无源；盘中值归 §3.6 option_quote_snapshot)
);
```

- **录入示例**（`UNIQUE(symbol, bar_date)` UPSERT，幂等）：
  ```python
  def store_option_daily(conn, rows):
      conn.executemany(
          """INSERT INTO option_daily
             (symbol, product_cd, bar_date, open, high, low, close, volume, oi)
             VALUES (:symbol, :product_cd, :bar_date, :open, :high, :low, :close, :volume, :oi)
             ON CONFLICT(symbol, bar_date) DO UPDATE SET
                close=excluded.close, open=excluded.open, high=excluded.high, low=excluded.low,
                volume=excluded.volume, oi=excluded.oi""",
          rows,
      )
  ```
  单条样例（`m2611-P-3000.DCE` 2026-10-16 实测真值；同一批 `m2611-C-3000.DCE` 的 bar 仍停在 10-15）：
  ```sql

  VALUES
    ('m2611-P-3000.DCE', 'm', '2026-10-16', 0.5, 0.5, 0.5, 0.5, 568, 14440);

    ('m2611-C-3000.DCE', 'm', '2026-10-15', 296, 296, 279, 279, 15, 1547);

  ```

### 3.6 期权盘口快照：option_quote_snapshot

- **用途**：**盘中盘口快照**（`last` / `bid` / `ask` / 买卖量），供实时选腿与 #1 盘口检查。
  按 §五「实时数据两分」约定**单开快照表**，**不写回 `option_daily` 日终行**——两套主键
  （`snapshot_time` vs `bar_date`）互不覆盖。
- **数据源**：主源 **tbpy** `get_current_tick(symbol=[...])`。
  - **必须传 list**（实测）：传单个字符串 → 返回 `None` 且不报错；
  - **限流**：1 次 / 60s、单次 ≤20 合约（超限报 `查询实时失败,查询限制,间隔=60000ms,合约数量=20`）→ 分批 + 62s 冷却；
  - **返回条数 ≤ 传入数**：无实时行情的合约**缺席且不报错** → 按 MISSING 处理，绝不拿邻近行权价插值。
- **实测结果**（2026-10-15 22:30 / 2026-10-14 夜盘）：
  ```
  2026-10-15 22:30 get_current_tick(['m2611.DCE', 4 个期权, 'au2612.SHFE']) → 返回 0 条、last_err=''
  2026-10-14 01:51 get_current_tick(['au2612.SHFE'])                       → last=898.20（真值）
  is_trading_time('m2611-C-3000.DCE') → False，同期 is_trading_time('m2611.DCE') → True
  ```
  1. **行情源未在线是"静默空"**：返回 0 条且 `last_err=''`（不报错）→ 不可据此判"无此合约"；
     缺即不写行，下游按 MISSING 处理。
  2. **期权 symbol 不能用来判交易时段**：`session_hours` 按 symbol 解析品种，期权代码被判 False
     → 盘中判定 / 取数前统一用**标的期货 symbol**。
- **抽取方法**：盘中按批拉取 → `UNIQUE(symbol, snapshot_time)` 追加（快照**只增不改**，与日线回填互不干扰）。

```sql
CREATE TABLE option_quote_snapshot (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol        TEXT,  -- 期权合约代码（→ option_info.symbol）
    snapshot_time TEXT,  -- 该 tick 时刻 YYYY-MM-DD HH:MM:SS.sss（← Tick.time，毫秒级）
    last          REAL,  -- 最新价（← Tick.last）
    bid           REAL,  -- 买价（盘口 1 档 ← BidAsk.bid_p）
    ask           REAL,  -- 卖价（盘口 1 档 ← BidAsk.ask_p）
    bid_vol       REAL,  -- 买量(手)（← BidAsk.bid_v）[可拉尽拉]
    ask_vol       REAL,  -- 卖量(手)（← BidAsk.ask_v）[可拉尽拉]
    pre_settle    REAL,  -- 昨结算（← Tick.pre_settlement）[可拉尽拉]
    UNIQUE (symbol, snapshot_time)
);
```

- **录入示例**（快照按 `snapshot_time` 追加，幂等）：
  ```python
  def store_option_quote(conn, rows):
      conn.executemany(
          """INSERT INTO option_quote_snapshot
             (symbol, snapshot_time, last, bid, ask, bid_vol, ask_vol, pre_settle)
             VALUES (:symbol, :snapshot_time, :last, :bid, :ask, :bid_vol, :ask_vol, :pre_settle)
             ON CONFLICT(symbol, snapshot_time) DO UPDATE SET
                last=excluded.last, bid=excluded.bid, ask=excluded.ask""",

      )
  ```
  单条样例（`au2612.SHFE` 2026-10-14 夜盘实测，期权同构）：

### 3.7 隐含波动率：option_iv

- **用途**：隐含波动率时点快照（非终态语义）。`iv` / `iv_atm` / `hv_*` / `iv_rank` / `iv_percentile` / `skew` 用于相对估值与择时（IV 高位卖、低位买）。业务上称"快照"，元数据归 `date_type='tick'` 档（实时、无终态），写模式 `store_mode='append_snapshot'`（见 §2.2）。
- **数据源**：**openvlab `/api/ctamap-all`**（品种级**主力月** `atmv_current` / `atmv_percentile` / `atmv_1dchg` / `skew` / `rv22`，实测覆盖 47/47，D13 已落地）。**注**：tbpy 无 iv 字段（`Tick`/`Bar`/`Instrument` 实测均无），"由 `option_daily` 逐合约 iv 聚合"**不成立**——合约级 IV 若日后要反解，另建派生表并带 `model` 标记，不并入本表。
- **抽取方法**：阶段一在交易时段 / 盘后按 `product_cd` 抓取 IV 快照 → `UNIQUE(product_cd, snapshot_time)` 真 upsert；**快照即时点，非收盘终态**（老化以 `snapshot_time` 日期部分判定，不另设 `bar_date`）。

```sql
CREATE TABLE option_iv (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    product_cd     TEXT,
    snapshot_time  TEXT,   -- 时点 YYYY-MM-DD HH:MM:SS（快照本质，非 bar_date）
    iv             REAL,   -- 隐含波动率（标的级，如平值）
    iv_atm         REAL,   -- 平值 IV [可拉尽拉]
    hv_20          REAL,   -- 20日历史波动率 [可拉尽拉]
    hv_60          REAL,   -- 60日历史波动率 [可拉尽拉]
    iv_rank        REAL,   -- IV 分位(0-100) [可拉尽拉]
    iv_percentile  REAL,   -- IV 百分位 [可拉尽拉]
    skew           REAL,   -- 偏度 [可拉尽拉]
    UNIQUE (product_cd, snapshot_time)
);
```

## 四、字段约定

- **口径**：`（后复权）`仅用于相对指标；`（不复权）`用于绝对价。混合即缺陷（需求文档 §二.1）。`main_contract_daily` 存**服务端后复权价**（换月后复权，来自 `RolloverBackWard`），其列注释标"（后复权）"；因后复权保值收益率，相对指标与锚定日无关（见 §三.1 / §五 复权锚定）。
- **单位**：价格=元；成交量=手；金额=元；`pct`/`_degree`=百分比；greeks 为原生值。
- **`[可拉尽拉]`**：表示数据源可取到、但当前策略暂未消费，仍**一律落库**，以备后续分析。
- **时间**：`bar_date` = **数据自身日期**（bar 的交易日，`YYYY-MM-DD`），是日线类业务表的分区 / 索引键；`pull_date` = **拉取动作发生日**（与数据内容无关），仅 `data_pull_detail`（及 account 表，账户快照即当日拉取）使用；快照类以 `snapshot_time`（YYYY-MM-DD HH:MM:SS）为完整时点。
- **数值精度**：数值字段统一用 `REAL`（价格 / 金额 / 比率 / greeks 等），**不**采用 INTEGER 最小单位方案（如"分"），以免引入 100 倍换算错误、且仍无法精确表达 0.0001 元价格。REAL 的浮点残差在**比较 / 累加处做好控制**：金额按业务精度四舍五入（如到分）、价格按最小变动价位；避免大量浮点连加；相等比较用 epsilon。
- **自增 id**：所有业务数据表首列统一加 `id INTEGER PRIMARY KEY AUTOINCREMENT`，仅用于标识数据写入先后、便于排查；原业务复合/单列主键**一律降为 `UNIQUE` 约束**保留去重语义（控制面 `data_storage_rule` / `data_state_check` / `data_pull_detail` 同样必须补 `UNIQUE`，否则 id 抢占主键后去重凭空消失）。**例外**：KV 表 `全局配置表` 与静态表（`future_info` / `option_info` / `trading_calendar` 类静态参考表）以业务键为 `PRIMARY KEY`，不加自增 id。
- **id 稳定即"先后"（重取纪律）**：`id` 要真实代表首次写入顺序，重取/重跑**必须用 `ON CONFLICT(业务 UNIQUE 键) DO UPDATE`（真 upsert，id 不变），禁用 `INSERT OR REPLACE`**（后者删+插会发新 id，打乱"先后"）。

## 五、关键关系与口径

- **三类时序数据约束（总览）**：本系统行情数据存在三类时序一致性问题，分别由下方专条约束——① **后复权锚漂移（事件驱动、对相对指标无碍）**：`main_contract_daily` 后复权绝对水平**并非每拉必变**，仅当两次拉取间隔内发生换月时历史事件的水平才会重算漂移；但后复权保值收益率，**相对指标与锚无关**，且本表仅用于相对指标，故实际无碍（见『复权锚定』）；落库存后复权价、相对指标单锚计算即可（整窗重写天然同锚）。② **盘中形成中 bar**：日线类 `bar_date == today` 行为收盘前临时值（见『终态性 / 盘中拉取』）；③ **实时数据瞬时性**：盘口 tick 仅盘中可获、只服务实时决策（见『实时数据分类』）。三者共同决定：哪些数据能落库、以何主键、何时为终态、相对指标须在同一锚 / 同一终态窗口内计算。
- **table_ref 关联（1:1）**：`data_state_check.table_ref` = `data_storage_rule.table_ref`，两表经此**一对一**关联（一个取数单元契约行 ↔ 一张表的当前状态行）；`data_state_check` 以 `bar_start_date` / `bar_end_date` 标识其核对覆盖的数据区间（而非拉取日），对账出"应有 vs 实有"。
- **品种关联**：业务表 `product_cd`（品种）/ `symbol`（合约）关联 `future_info.product_cd`，取乘数 / 保证金金额（单腿 `margin_per_lot` / 实际占用 `actual_margin_per_lot`，见 §2.5）。
- **时间维度 / 分区**：日线类业务表含 `bar_date`（数据日期），跨日自动失效，不拿旧数据当新；**快照类**（如 `option_iv`）以 `snapshot_time`（YYYY-MM-DD HH:MM:SS）为时间维度，**不另设 `bar_date`**——其日期部分即归属日，承担老化 / 去重，无需重复列。控制面 `data_state_check` **不存 `pull_date`**，改以 `bar_start_date` / `bar_end_date` 标识其核对覆盖的数据区间（描述"齐了哪段数据"，而非"哪天拉的"）。
- **价格口径**：`main_contract_daily` 后复权（相对指标），其余不复权（绝对价）——检查逻辑须严格分流。
- **终态性与四态映射**：日线类（`bar`）**收盘后为终态** → 检查程序据此将 `status` 置 `normal`；盘中 `bar_date==today` 的形成中 bar 视为"尚未定稿"，`status` 停留在 `fetching`（等待），不消费未定稿数据，收盘后重拉定稿再转 `normal`。`option_iv`（`tick`）快照即时点、无终态语义，按新鲜度判 `normal`/`abnormal`；`static`（如 `trading_calendar`）存在即终。`normal`/`abnormal` 的具体判定由检查程序按 `date_type` 实现（见 §2.3）。
- **实时/静态档就绪判据（检查程序实现）**：`date_type='tick'`（实时/快照，如 `option_iv`）不以计数核对，而以**新鲜度**为就绪判据——当日内须已产生快照且 `snapshot_time` 落在最近交易时段内，越窗即判 `abnormal`；具体新鲜度窗口由检查程序配置。`date_type='static'`（如 `trading_calendar`）以**完整性**核对（覆盖预期区间 / 存在即终），非每日计数，判 `normal`/`abnormal`。
- **盘中拉取（形成中 bar）处理**：日线类在交易时段内拉到的 `bar_date == today` 行是**形成中 bar**（`close` 非当日最终收盘），**不得直接用于相对指标 / 绝对价结论**。三层处理：(a) **读侧**：对 `bar_date == today` 且未过收盘时点的行硬判"形成中"、排除出 #3 市况 / #10 否决等指标，最新有效点取上一已完成交易日；(b) **门控**：阶段二判 `bar` 收盘前为形成中，将当日 `data_state_check.status` 维持在 `fetching`（视为尚未定稿、等待），阶段三不消费 `fetching` 数据，盘中只产出"待收盘 / 粗筛"结论、绝不硬下绝对价；(c) **回填**：收盘后阶段一以 `use_cache=False` 对刚收盘交易日**强制重拉回填**，定稿后检查程序将 `status` 转 `normal`。盘口 tick（`option_quote_snapshot.bid/ask/last`、premium）是**某时刻真实快照**，仅用于盘中实时选腿 / 定价，不得替代日线 `close` 作历史绝对价基准。
- **实时数据（盘口 tick / 快照）分类**：实时数据分两类处理——(a) **瞬时盘口 tick**（live premium、live IV）：盘中实时选腿 / 定价 / 盘口检查（#1）用之，纯瞬时、**不落日线类业务表**，扫描结束即弃；(b) **需留痕的实时值**：以**快照表 + `snapshot_time`（YYYY-MM-DD HH:MM:SS）**方式落库（范例 `option_iv`、期权盘口 `option_quote_snapshot`），用于复盘 / 审计 / 跨日比对，且**不与日终定稿行互相覆盖**——快照按 `snapshot_time` upsert、日线按 `bar_date` upsert，两套主键互不干涉。**期权盘口快照已按此约定单开 `option_quote_snapshot`（§3.6），禁止写回 `option_daily` 日终行**。
- **复权锚定（后复权序列的时点依赖）**：`main_contract_daily` 存**服务端后复权价**（来自 `RolloverBackWard`）。后复权为**乘性平移、保值收益率**：同一连贯拉取内任意两日之比 = 真实收益率，**与锚定日无关**；本表为 `full_window_rewrite`（整窗 DELETE + 全窗 INSERT），同标的每次拉取天然共用同一锚，不存在跨锚混算。故本表**仅用于相对指标**（收益率 / ADX / 区间位置），锚对其**无实质影响**；只有"拿后复权绝对价当价格"才会出错（已被"价格口径两分"铁律禁止）。处理：(a) 落库存**服务端后复权价**，弃用原始价 / 调整因子方案——tbpy `QuoteFlag` 仅 `RolloverBackWard` 一个复权枚举、无独立"原始价" flag（原始价需 `flag=None` 额外拉取，且对相对指标无益），故只拉一次 `RolloverBackWard` 即可；(b) 不复权表（`contract_daily` / `option_daily` 的 OHLC）是真实成交价、不随锚定日变；`future_tick` 为单值 tick 快照（同属不复权、不随锚变），无 OHLC 序列。二者皆无此问题。（**实证**：本机 `strategies/sell_option/sell_option/data/daily.db` 的 `index_daily` 表（v1 旧名，本设计对应 `main_contract_daily`）中，`m9888.DCE` 在 `2026-09-30` / `10-08` / `10-09` 三次拉取的 298 个共同历史日，后复权收盘价**完全一致**——实测无漂移，印证整窗单锚下相对指标安全。）
