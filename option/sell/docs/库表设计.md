# option.sell 库表设计（v2）

> 配套 `docs/需求文档.md` §六/§七。本系统**数据驱动**，库表是地基：先定 schema，再写三阶段流水线（拉取 → 检查 → 报表）与策略逻辑。
> 设计原则：
> 1. **业务数据**与**控制面**分离（逻辑上）：二者同处一个库文件 `option.db`，但用**不同的表**区分——业务数据表（§二）与控制面表（§三）互不混写，权限 / 生命周期也不同。
> 2. **价格口径两分**（承接需求文档 §二.1）：连续指数日线用**后复权**，仅供相对指标；合约 / 现货 / 权利金用**不复权**，供一切绝对价。混用即缺陷。
> 3. **日线类**业务表按 `pull_date`（归属交易日）分区 / 建索引；**快照类**（如 `option_iv`，见 §二.5）以 `snapshot_time` 为时间维度、不另设 `pull_date`。**实时数据两分**：盘口 tick（`bid`/`ask`/`last`、live premium、live IV）属"此刻"瞬时值，仅用于盘中实时选腿 / 定价，**不写为日线类业务表的定稿行**；确需保留的实时值（如 `option_iv` 的 IV 快照）以**快照表 + `snapshot_time` 完整时点**方式落库，不与日终定稿行混淆（详见 §五）。
> 4. **命名规范**：全系统**单一库文件** `option.db`（不再一表一库）；**表名**一律**两词以上**且**与 v1 严格区分**（v1 用单词名如 `spot`/`iv`/`position`/`capital`，v2 改为 `underlying_spot`/`option_iv`/`account_position`/`account_capital`/`trading_calendar`/`option_chain`/`index_daily`/`contract_daily` 等）；字段须定义清楚（口径 / 单位 / 来源）。
> 5. **可拉尽拉**：凡是数据源能取到的字段——即使当前策略暂未使用——也**一律落库存储**，不得因"暂时不用"而丢弃（避免日后分析时无数据）。
> 6. 旧 `strategies/sell_option/` 的表结构**不沿用**，本文件为全新首稿。

## 二、业务数据表（库：option.db）

> 下列 8 张表均为**业务数据**，由阶段一拉取、阶段二检查、阶段三消费（读写归属见 §六）。
> 每张表统一给出 **用途 / 数据源 / 抽取方法** 三项说明；字段口径、单位、时间格式、可拉尽拉见 §四。**注意**：各表下方描述仅为便于人读，其取值（数据源 / 窗口 / 写模式 / 终态 / 应有实体）以 §三.2 `data_storage_rule` 为**唯一契约**，二者冲突以该表为准。
> 数据源候选集统一为 **tbpy / openvlab / 新浪(sina) / manual**（需求文档 §6.2），主源与备选的优先级由 `全局配置表` `source.*` 键配置；实际可用性见 §七 Q1。

### 2.1 指数日线：index_daily

- **用途**：**主连后复权日线**（连续合约、服务端 `RolloverBackWard` 换月后复权）。注意本系统"指数"指**主连连续合约（888 后缀，如 `m9888.DCE` / `rb888.SHFE` / `IF888.CFFEX`）**，非股票指数；后复权在此即"换月后复权"，用于抹平主力换月跳空。**仅服务于相对指标**——收益率、波动率、趋势、ADX、区间位置；绝不用于任何绝对价（价格口径两分铁律，需求文档 §二.1）。
- **数据源**：**tbpy（唯一已实现源）**——`tbpy.get_history_n(symbol, "1d", count, fields, flag=tbpy.QuoteFlag.RolloverBackWard)` 取**服务端后复权**日线（旧 `d12_index_daily.py` 即如此；`tbpy方法参考` 确认 `RolloverBackWard` 是连续合约唯一复权枚举，无独立"原始价" flag——原始价须 `flag=None`（`QuoteFlag.Null`）另行拉取，但本表**只需后复权**，故只拉一次 `RolloverBackWard` 即可，省一次昂贵的 `get_history_n` 调用）。备选 **新浪**（§七 Q1 开放项，待验证）。
- **抽取方法**：阶段一每日盘后据 `data_storage_rule`（`table_ref='index_daily'`）预取 → `get_history_n(symbol, "1d", count=pull_count, fields, flag=RolloverBackWard)` 拉**调整后 OHLC**。窗口 `pull_count` 默认 **300 条（≈1.2 年日线，覆盖 ADX / 波动率 / 区间百分位回看）**，由 `data_storage_rule.pull_count` 驱动、**整窗拉取**（非仅拉新 bar）——因后复权须单锚一致，增量 append 会把新锚行与旧锚行混在同一窗口，换月后相对指标算错（机理见 §五 复权锚定）。**落库方式 = `store_mode='full_window_rewrite'`**：按 `index_code` 整段全量重写（事务内先 DELETE 该标的历史窗口、再 INSERT 本批全窗，全批共用同一 `adj_ref_date` = 本次拉取日）；`UNIQUE(index_code, trade_date)` 仍保留防意外重复插入；同日重拉命中缓存跳过，幂等。**收盘后为终态**（由 `date_type='bar'` 派生，见 §3.2）。相对指标须在**同一 `adj_ref_date` 窗口**内计算，切勿跨不同锚定日混算（按批同锚天然避免）。（对照：不复权表 `contract_daily` / `underlying_spot` / `option_chain` 真实价不可变，用 `store_mode='incremental_upsert'` 安全追加新 bar；后复权表不可增量，须整窗重写。）

```sql
CREATE TABLE index_daily (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    index_code   TEXT,    -- 主连连续合约代码，如 m9888.DCE / rb888.SHFE / IF888.CFFEX
    trade_date   TEXT,    -- 交易日 YYYY-MM-DD
    open         REAL,    -- 开盘价（后复权，换月后复权）
    high         REAL,    -- 最高价（后复权）
    low          REAL,    -- 最低价（后复权）
    close        REAL,    -- 收盘价（后复权）
    pre_close    REAL,    -- 昨收（后复权）[可拉尽拉]
    volume       REAL,    -- 成交量（手）
    amount       REAL,    -- 成交额（元）
    turnover     REAL,    -- 换手率(%) [可拉尽拉]
    vwap         REAL,    -- 均价（后复权）[可拉尽拉]
    adj_ref_date TEXT,    -- 复权锚定日（本批拉取日；同批同值，用于相对指标单锚一致性校验）
    UNIQUE (index_code, trade_date)
);
```

### 2.2 合约日线：contract_daily

- **用途**：月度合约日线（不复权）。**用于一切绝对价**——现价、行权价、权利金、保证金、安全垫、封顶、肥瘦。与 `index_daily` 严格分流（混用即缺陷）。
- **数据源**：建议 **tbpy**（期权合约日线主源）；备选 **openvlab**。
- **抽取方法**：阶段一每日盘后预取 → 按标的 / 到期月拉合约日线（OHLC / 昨收 / 结算 / 量 / 额 / 持仓）→ `UNIQUE(symbol, trade_date)` 真 upsert 落库；收盘后终态。

```sql
CREATE TABLE contract_daily (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol       TEXT,    -- 合约代码
    underlying   TEXT,    -- 标的代码
    expire       TEXT,    -- 到期月 YYYY-MM
    trade_date   TEXT,
    open         REAL,    -- 开盘（不复权）
    high         REAL,
    low          REAL,
    close        REAL,
    pre_close    REAL,    -- 昨收 [可拉尽拉]
    settle       REAL,    -- 结算价
    volume       REAL,    -- 成交量
    amount       REAL,    -- 成交额 [可拉尽拉]
    oi           REAL,    -- 持仓量
    UNIQUE (symbol, trade_date)
);
```

### 2.3 现货：underlying_spot

- **用途**：标的最新现货价（不复权）。绝对价基准——现价、行权价、安全垫、封顶、肥瘦判定。
- **数据源**：**tbpy**（现货盘口 / 日线，`get_current_tick` / `get_history_n`）；备选 **新浪**。
- **抽取方法**：阶段一盘后预取 → 按 `underlying` 拉现货日线（OHLC / 昨收 / 量 / 额 / 换手 / 均价）→ `UNIQUE(underlying, trade_date)` 真 upsert；收盘后终态。

```sql
CREATE TABLE underlying_spot (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    underlying   TEXT,    -- 标的代码
    trade_date   TEXT,
    open         REAL,    -- 开盘（不复权）
    high         REAL,
    low          REAL,
    close        REAL,    -- 现货收盘价（不复权）
    pre_close    REAL,
    volume       REAL,
    amount       REAL,
    turnover     REAL,    -- 换手率 [可拉尽拉]
    vwap         REAL,    -- 均价 [可拉尽拉]
    UNIQUE (underlying, trade_date)
);
```

### 2.4 期权链：option_chain

- **用途**：期权链盘口与权利金、greeks、保证金（不复权）。选腿、定价、保证金、封顶价差、肥瘦检查均依赖此表；`iv` / `delta` 等衍生列可拉尽拉先存。
- **数据源**：**tbpy**（`get_instrument` 取合约元数据 + 盘口 / 日线）；备选 **openvlab**（greeks / IV 更全时降级）。
- **抽取方法**：阶段一每日盘后预取 → 按标的拉全合约链（行情 + 盘口 + greeks + 保证金 + 状态）→ `UNIQUE(symbol, trade_date)` 真 upsert；收盘后终态（盘中实时价不落库）。

```sql
CREATE TABLE option_chain (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol         TEXT,   -- 合约代码
    underlying     TEXT,   -- 标的
    expire         TEXT,    -- 到期月 YYYY-MM
    strike         REAL,   -- 行权价
    type           TEXT,   -- C 认购 / P 认沽
    trade_date     TEXT,
    pre_settle     REAL,   -- 昨结算 [可拉尽拉]
    open           REAL,
    high           REAL,
    low            REAL,
    close          REAL,
    settle         REAL,   -- 结算价
    last           REAL,   -- 最新价
    bid            REAL,   -- 买价
    ask            REAL,   -- 卖价
    bid_vol        REAL,   -- 买量(手) [可拉尽拉]
    ask_vol        REAL,   -- 卖量(手) [可拉尽拉]
    volume         REAL,   -- 成交量
    amount         REAL,   -- 成交额 [可拉尽拉]
    oi             REAL,   -- 持仓量
    theo_price     REAL,   -- 理论价 [可拉尽拉]
    iv             REAL,   -- 隐含波动率(合约级) [可拉尽拉]
    delta          REAL,   -- 希腊值 [可拉尽拉]
    gamma          REAL,   -- 希腊值 [可拉尽拉]
    vega           REAL,   -- 希腊值 [可拉尽拉]
    theta          REAL,   -- 希腊值 [可拉尽拉]
    rho            REAL,   -- 希腊值 [可拉尽拉]
    margin         REAL,   -- 单张保证金 [可拉尽拉]
    status         TEXT,   -- 交易状态 trading/halted [可拉尽拉]
    UNIQUE (symbol, trade_date)
);
```

### 2.5 隐含波动率：option_iv

- **用途**：隐含波动率时点快照（非终态语义）。`iv` / `iv_atm` / `hv_*` / `iv_rank` / `iv_percentile` / `skew` 用于相对估值与择时（IV 高位卖、低位买）。业务上称"快照"，元数据归 `date_type='tick'` 档（实时、无终态），写模式 `store_mode='append_snapshot'`（见 §3.2）。
- **数据源**：**tbpy / `option_chain.iv` 派生**（逐合约 iv 聚合为标的级 IV / 平值 IV / 历史波动率）；备选 **openvlab**（含更全 IV 曲面时）。
- **抽取方法**：阶段一在交易时段 / 盘后按 `underlying` 抓取 IV 快照 → `UNIQUE(underlying, snapshot_time)` 真 upsert；**快照即时点，非收盘终态**（老化以 `snapshot_time` 日期部分判定，不另设 `pull_date`）。

```sql
CREATE TABLE option_iv (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    underlying     TEXT,
    snapshot_time  TEXT,   -- 时点 YYYY-MM-DD HH:MM:SS（快照本质，非 trade_date）
    iv             REAL,   -- 隐含波动率（标的级，如平值）
    iv_atm         REAL,   -- 平值 IV [可拉尽拉]
    hv_20          REAL,   -- 20日历史波动率 [可拉尽拉]
    hv_60          REAL,   -- 60日历史波动率 [可拉尽拉]
    iv_rank        REAL,   -- IV 分位(0-100) [可拉尽拉]
    iv_percentile  REAL,   -- IV 百分位 [可拉尽拉]
    skew           REAL,   -- 偏度 [可拉尽拉]
    UNIQUE (underlying, snapshot_time)
);
```

### 2.6 交易日历：trading_calendar

- **用途**：交易日历。驱动预取时机、终态判定、跨日老化、长假 / 破位提醒。
- **数据源**：**manual**（由本地 `manual_calendar` 逐日播种，已本地化，不再依赖 tbpy.is_holiday / 外部日历）。
- **抽取方法**：阶段一每日或低频预取 → 写入 `trade_date` + 衍生标志（月末 / 季末 / 年末 / 邻长假）→ `trade_date UNIQUE` 真 upsert；静态参考表，非逐日终态。

```sql
CREATE TABLE trading_calendar (
    id                    INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    trade_date            TEXT UNIQUE, -- 交易日 YYYY-MM-DD
    is_trading_day        INTEGER,  -- 1 交易日 / 0 非
    is_month_end          INTEGER,
    is_quarter_end        INTEGER,  -- [可拉尽拉]
    is_year_end           INTEGER,  -- [可拉尽拉]
    prev_trade_date       TEXT,    -- 上一交易日 [可拉尽拉]
    next_trade_date       TEXT,    -- 下一交易日 [可拉尽拉]
    pre_long_holiday_days   INTEGER,  -- 距前一长假天数
    post_long_holiday_days  INTEGER,  -- 距后一长假天数
    holiday_name          TEXT,    -- 临近长假名 [可拉尽拉]
    remark                TEXT
);
```

### 2.7 账户持仓：account_position（券商账户真实数据）

- **用途**：账户真实持仓（权利仓 / 义务仓）。风险暴露、保证金占用、浮动盈亏、距到期。
- **数据源**：**券商账户接口 / manual 导出**（真实数据，非行情源；v1 经验：账户数据须以券商为准，不得用行情反推）。
- **抽取方法**：阶段一从券商接口 / 导出文件拉取当日持仓 → `UNIQUE(symbol, pull_date)` 真 upsert；`pull_date` 为归属交易日（盘后终态）。

```sql
CREATE TABLE account_position (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol          TEXT,
    underlying      TEXT,
    expire          TEXT,
    strike          REAL,
    type            TEXT,    -- C/P
    pull_date       TEXT,
    side            TEXT,    -- long 权利仓 / short 义务仓
    quantity        REAL,    -- 持仓量（义务仓为负）
    avg_cost        REAL,    -- 开仓均价
    last_price      REAL,   -- 最新价 [可拉尽拉]
    underlying_price REAL,   -- 标的最新价 [可拉尽拉]
    market_value    REAL,    -- 市值 [可拉尽拉]
    unrealized_pnl  REAL,    -- 浮动盈亏 [可拉尽拉]
    margin_occupied REAL,    -- 占用保证金 [可拉尽拉]
    delta_exposure  REAL,    -- Delta 暴露 [可拉尽拉]
    expiry_days     REAL,    -- 距到期天数 [可拉尽拉]
    open_date       TEXT,    -- 开仓日 [可拉尽拉]
    status          TEXT,    -- 持仓状态 [可拉尽拉]
    UNIQUE (symbol, pull_date)
);
```

### 2.8 账户资金：account_capital

- **用途**：账户资金与预算。仓位上限、资金约束、风险度。
- **数据源**：**券商账户接口 / manual 导出**（真实数据）。
- **抽取方法**：阶段一从券商接口 / 导出文件拉取当日资金 → `pull_date UNIQUE` 真 upsert；盘后终态。

```sql
CREATE TABLE account_capital (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    pull_date        TEXT UNIQUE, -- 归属交易日 YYYY-MM-DD
    total_asset      REAL,  -- 总资产 [可拉尽拉]
    available        REAL,  -- 可用资金
    cash             REAL,  -- 现金
    frozen           REAL,  -- 冻结资金 [可拉尽拉]
    margin_used      REAL,  -- 已用保证金
    margin_available REAL,  -- 可用保证金 [可拉尽拉]
    positions_value  REAL,  -- 持仓市值 [可拉尽拉]
    risk_degree      REAL,  -- 风险度(%) [可拉尽拉]
    profit           REAL,  -- 当日盈亏 [可拉尽拉]
    remark           TEXT
);
```

## 三、控制面（库：option.db）

> 控制面 4 张表与业务数据同库（见 §一），但逻辑隔离、互不混写（设计原则 1）。其数据**非外部行情拉取**，而是由系统生成或 manual 维护。

### 3.1 全局配置表（KV 表）

- **用途**：系统级 KV 配置——数据源优先级与降级顺序（`source.*`）、预取时机（`schedule.*`）、门控严格度（`gate.*`）、库路径（`path.db`）等固定开关。阶段二 / 三只读消费。
- **数据源**：**manual**（手工维护 / 启动加载），非外部行情拉取。
- **抽取方法**：初始化时写入或 `UPSERT`；以 `key` 为主键，不加自增 id（见 §四）。

```sql
CREATE TABLE 全局配置表 (
    key         TEXT PRIMARY KEY,  -- 配置项名（含分组前缀，如 source.tbpy_priority / path.db）
    value       TEXT,              -- 配置值
    remark      TEXT,              -- 说明
    create_time TEXT,              -- 创建时间 YYYY-MM-DD HH:MM:SS
    update_time TEXT               -- 最后更新时间 YYYY-MM-DD HH:MM:SS
);
```
> KV 配置表以业务 `key` 为主键，**不加自增 id**（避免"重复 key"有后路）。

### 3.2 data_storage_rule（数据存储规则表）

- **用途（表名 `data_storage_rule`，中文名「数据存储规则表」）**：阶段零元数据 + **取数 / 存储 / 维护的唯一契约**。它本身不落业务数据，只声明"每张业务表该怎么取、怎么存、怎么维护"，是阶段一 / 二 / 三读取配置的总入口。
  - **粒度**：一行 = 一个取数单元（以 `table_ref` 标识），即**一表一取数单元**（如 `index_daily` 一张表、一种后复权取数方式，覆盖 `product_boundary` 中全部活跃主连）；数据源记于 `data_source` 单列（不设降级列）。
  - **字段语义**：
    - `table_ref`：落到哪张物理表；同时充当**取数单元唯一键**，以及与 `data_state_check` 对账的连接键（`UNIQUE`）。
    - `table_name`：表名（人读，区别于 `table_ref` 的物理表引用；如 '主连后复权日线'）。
    - `date_type`：数据类型的**元数据**（Tbquant 定义名 `bar` / `tick` / `static`，不翻译）。本表仅做分类标注，**下游各规则据此施管**：bar→日线终态判定、static→存在即终、tick→无终态（tick 档含实时瞬时值与快照，如 `option_iv`；快照写模式对应 `store_mode='append_snapshot'`，`date_type` 与 `store_mode` 维度不同、不冲突）。
    - `data_source`：主数据源（如 `tbpy`）。
    - `pull_method`：拉取方式（`post_close` / `intraday` / `event` / `low_freq`；`low_freq` 用于低频/静态单元如 `trading_calendar`）。
    - `pull_count`：每次拉取的**回溯条数**，**按每标的计**（index_daily=300 为整窗重拉；incremental_upsert 表仅取新 bar，`pull_count=1`；实时/static 档留空）。
    - `store_mode`：落库模式，取值各对应一档数据：`incremental_upsert`→不复权档（如 `contract_daily`）/ `full_window_rewrite`→后复权档（如 `index_daily`）/ `append_snapshot`→实时快照档（如 `option_iv`）。
    - `required_fields`：必填非空字段，字段级缺失检。
    - `status`：状态（1=有效/0=无效；有效=纳入应有效验，无效=旁路不拉不校验、不报错）。
  - **三阶段驱动**：①阶段一按本表逐行拉取并落库；②阶段二据 `date_type` 派生"应有"（bar：`pull_count` × `product_boundary` 活跃实体数；tick/static 口径见 `data_state_check`）、据 `date_type` 派生终态（见 `date_type` 字段语义）标 non_terminal；③阶段三门控据终态判定放行。
  - **与 `data_state_check` 对账**：两表经 `table_ref` 关联——本表给"应有"（预期条数），`data_state_check` 记"实有"（actual_n / status），对不上的即缺数据 / 脏 / 未终态（§五）。
  - **单一事实源**：§二 各表"用途 / 数据源 / 抽取方法"仅为人读说明，其取值（数据源 / 窗口 / 写模式 / 应有实体）以本表为准，冲突优先本表。

- **数据源 / 维护**：**manual**（设计期固化），随 schema 设计写入、状态 `status`；系统启动加载为期望基线。

- **一致性约束**：各业务表须按 §四 在其上建立 `UNIQUE` 约束以保证去重（本表不另存去重键）；`store_mode` / `date_type` 取值须与对应业务表实际取数 / 存储方式一致。

```sql
CREATE TABLE data_storage_rule (
    id INTEGER PRIMARY KEY AUTOINCREMENT,            -- 自增主键
    table_ref    TEXT UNIQUE,   -- 物理表引用（取数单元唯一键 + 对账连接键）
    table_name   TEXT,          -- 表名（人读）
    date_type    TEXT,          -- 数据类型
    data_source  TEXT,          -- 主数据源
    pull_method  TEXT,          -- 拉取方式
    pull_count   INTEGER,       -- 每标的回溯条数（实时档留空）
    store_mode   TEXT,          -- 落库模式
    required_fields TEXT,       -- 必填非空字段清单（逗号分隔列名）
    status       INTEGER DEFAULT 1,  -- 状态（1=有效/0=无效）
    remark       TEXT,          -- 备注
    create_time  TEXT,          -- 创建时间
    update_time  TEXT           -- 更新时间
);
```

> **示例（每个取数单元一行，仅列关键字段）**
> - **`index_daily`（主连后复权日线）**：`table_ref='index_daily'`、`date_type='bar'`、`data_source='tbpy'`、`pull_method='post_close'`、`pull_count=300`（每标的 300 条）、`store_mode='full_window_rewrite'`（`flag=RolloverBackWard`、全批共用 `adj_ref_date`，**非增量**保证单锚）。
> - **`contract_daily`（不复权）**：`date_type='bar'`、`store_mode='incremental_upsert'`（每日仅取新 bar，`pull_count=1`；历史窗口逐日累积，非整窗重拉）。
> - **`option_iv`（实时快照）**：`date_type='tick'`、`pull_method='intraday'`、`store_mode='append_snapshot'`、`pull_count` 留空（盘中现拉、错过即 MISSING 不可补）。

### 3.3 data_state_check（数据状态核对表）

- **用途（表名 `data_state_check`，中文名「数据状态核对表」）**：阶段三**门控唯一事实来源**。逐源逐日登记某张表的拉取状态与质检结果，供阶段三判定"能不能放行 / 差在哪"。它本身不存"期望条数"——期望由 `data_storage_rule` 按 `date_type` 派生：bar 为 `pull_count` × `product_boundary` 活跃实体数（计数）；tick 为新鲜度（快照存在且落在交易时段内，阈值见 §五，非计数）；static 为完整性（覆盖预期区间 / 存在即终）。仅在此登记"实际"侧。
  - **字段语义**：
    - `id`：自增主键，仅标识写入先后。
    - `table_ref`：连接键，与 `data_storage_rule.table_ref` 同值，是对账主键之一。
    - `pull_date`：拉取日；与 `table_ref` 组成契约主键 `(table_ref, pull_date)`（见 §四 id 纪律）。
    - `status`：单一状态机，驱动全部门控（不再单列 `phase`）。流转：`pending`（已登记、待拉取）→ `fetching`（拉取中）→ `validating`（校验中）→ 终局之一：`ready`（通过、可放行）/ `missing`（缺数据）/ `dirty`（脏数据）/ `non_terminal`（数据在但非终态，如日线未收盘）。门控口径：仅 `ready` 放行；`missing` / `dirty` 阻塞（错误）；`pending` / `fetching` / `validating` / `non_terminal` 等待。
    - `actual_n`：实拉条数（与派生期望比对）。
    - `missing_fields`：字段级缺失计数。
    - `non_terminal_n`：未达终态条数（如日线尚未收盘）。
    - `last_fetch_at` / `last_validate_at`：最近拉取 / 校验时间。
    - `retry_count`：重试次数 [可拉尽拉]。
    - `err_msg`：具体失败信息（如缺失字段清单 / 非终态品种 / 异常原因），承接原明细表的逐项 `reason`。
  - **与 `data_storage_rule` 对账**：本表给"实有"（actual_n / status），`data_storage_rule` 给"应有"——按 `date_type` 分支：bar 为 `pull_count` × `product_boundary` 活跃实体数；tick 为新鲜度（见 §五，非计数）；static 为完整性（存在即终）；终态判定亦据 `date_type` 派生，对不上的即缺数据 / 脏 / 未终态（§五）。
  - **不使用外键**：仅以业务键 `(table_ref, pull_date)` 软引用；`id` 仅表写入先后、随 upsert 会变，挂外键会悬空，故两表以业务键对账、无需外键。

- **数据源 / 写入**：**系统生成**——阶段一创建行置 `pending`、启动拉取置 `fetching`、拉完置 `validating`，阶段二写校验结果置 `ready` / `missing` / `dirty` / `non_terminal`；每轮预取 / 校验后 upsert。

```sql
CREATE TABLE data_state_check (
    id INTEGER PRIMARY KEY AUTOINCREMENT,   -- 自增主键
    table_ref TEXT,                         -- 连接键（= data_storage_rule.table_ref，对账主键之一）
    pull_date TEXT,                         -- 拉取日（与 table_ref 组契约主键）
    status    TEXT,                         -- 单一状态机：pending→fetching→validating→(ready|missing|dirty|non_terminal)；仅 ready 放行
    actual_n INTEGER,                       -- 实拉条数（与派生期望比对）
    missing_fields INTEGER,                 -- 字段级缺失计数
    non_terminal_n INTEGER,                 -- 未达终态条数（如日线尚未收盘）
    last_fetch_at TEXT,                     -- 最近拉取时间
    last_validate_at TEXT,                  -- 最近校验时间
    retry_count INTEGER DEFAULT 0,          -- 重试次数 [可拉尽拉]
    err_msg     TEXT,                       -- 具体失败信息（缺失字段/非终态品种/异常原因）
    remark TEXT,                            -- 备注
    create_time TEXT, update_time TEXT,     -- 创建/更新时间
    UNIQUE (table_ref, pull_date)
);
```

- **数据源**：**manual**（v2 自建，不沿用旧 `品种边界表.md` 实数），可接口获取或手工维护。
- **抽取方法**：初始化写入 / 维护；以 `underlying` 为主键，不加自增 id。

CREATE TABLE product_boundary (

## 四、字段约定

- **口径**：`（后复权）`仅用于相对指标；`（不复权）`用于绝对价。混合即缺陷（需求文档 §二.1）。`index_daily` 存**服务端后复权价**（换月后复权，来自 `RolloverBackWard`），其列注释标"（后复权）"；因后复权保值收益率，相对指标与锚定日无关（见 §二.1 / §五 复权锚定）。
- **单位**：价格=元；成交量=手；金额=元；`pct`/`_degree`=百分比；greeks 为原生值。
- **`[可拉尽拉]`**：表示数据源可取到、但当前策略暂未消费，仍**一律落库**，以备后续分析。
- **时间**：`trade_date` 与 `pull_date` **同义**，均为归属交易日 `YYYY-MM-DD`（设计原则 3 / §五"按 pull_date 分区"对二者一致适用）；`snapshot_time` = 完整时点（快照类）。
- **数值精度**：数值字段统一用 `REAL`（价格 / 金额 / 比率 / greeks 等），**不**采用 INTEGER 最小单位方案（如"分"），以免引入 100 倍换算错误、且仍无法精确表达 0.0001 元价格。REAL 的浮点残差在**比较 / 累加处做好控制**：金额按业务精度四舍五入（如到分）、价格按最小变动价位；避免大量浮点连加；相等比较用 epsilon。
- **自增 id**：所有业务数据表首列统一加 `id INTEGER PRIMARY KEY AUTOINCREMENT`，仅用于标识数据写入先后、便于排查；原业务复合/单列主键**一律降为 `UNIQUE` 约束**保留去重语义（控制面 `data_storage_rule` / `data_state_check` 同样必须补 `UNIQUE`，否则 id 抢占主键后去重凭空消失）。**例外**：KV 表 `全局配置表` 与静态表 `product_boundary` 以业务键为 `PRIMARY KEY`，不加自增 id。
- **id 稳定即"先后"（重取纪律）**：`id` 要真实代表首次写入顺序，重取/重跑**必须用 `ON CONFLICT(业务 UNIQUE 键) DO UPDATE`（真 upsert，id 不变），禁用 `INSERT OR REPLACE`**（后者删+插会发新 id，打乱"先后"）。

## 五、关键关系与口径

- **三类时序数据约束（总览）**：本系统行情数据存在三类时序一致性问题，分别由下方专条约束——① **后复权锚漂移（事件驱动、对相对指标无碍）**：`index_daily` 后复权绝对水平**并非每拉必变**，仅当两次拉取间隔内发生换月时历史事件的水平才会重算漂移；但后复权保值收益率，**相对指标与锚无关**，且本表仅用于相对指标，故实际无碍（见『复权锚定』）；落库存后复权价 + `adj_ref_date`、相对指标单锚计算即可。② **盘中形成中 bar**：日线类 `trade_date == today` 行为收盘前临时值（见『终态性 / 盘中拉取』）；③ **实时数据瞬时性**：盘口 tick 仅盘中可获、只服务实时决策（见『实时数据分类』）。三者共同决定：哪些数据能落库、以何主键、何时为终态、相对指标须在同一锚 / 同一终态窗口内计算。
- **table_ref 关联**：`data_state_check.table_ref` = `data_storage_rule.table_ref`，是对账主键（应有 vs 实有）。
- **品种关联**：业务表 `underlying` / `symbol` 关联 `product_boundary.underlying`，取乘数 / 保证金率。
- **时间维度 / 分区**：日线类业务表含 `pull_date` / `trade_date`，跨日自动失效，不拿旧数据当新；**快照类**（如 `option_iv`）以 `snapshot_time`（YYYY-MM-DD HH:MM:SS）为时间维度，**不另设 `pull_date`**——其日期部分即归属日，承担老化 / 去重，无需重复列。
- **价格口径**：`index_daily` 后复权（相对指标），其余不复权（绝对价）——检查逻辑须严格分流。
- **终态性**：`option_iv` 是快照、非终态；其余日线类**收盘后为终态**；具体由 `date_type` 派生（`bar`→收盘后终态、`static`→存在即终、`tick`→无终态，见 §3.2）。
- **实时/静态档就绪判据**：`date_type='tick'`（实时/快照，如 `option_iv`）不以计数核对，而以**新鲜度**为就绪判据——当日内须已产生快照且 `snapshot_time` 落在最近交易时段内，越窗即判 `missing`；具体新鲜度窗口由实现层配置（不在此元数据表）。`date_type='static'`（如 `trading_calendar`）以**完整性**核对（覆盖预期区间 / 存在即终），非每日计数。
- **盘中拉取（形成中 bar）处理**：日线类在交易时段内拉到的 `trade_date == today` 行是**形成中 bar**（`close` 非当日最终收盘），**不得直接用于相对指标 / 绝对价结论**。三层处理：(a) **读侧**：对 `trade_date == today` 且未过收盘时点的行硬判"形成中"、排除出 #3 市况 / #10 否决等指标，最新有效点取上一已完成交易日；(b) **门控**：阶段二据 `date_type` 派生终态（bar 收盘前为形成中）把当日行标 `non_terminal`（`data_state_check.non_terminal_n` 计数），阶段三不消费未终态数据，盘中只产出"待收盘 / 粗筛"结论、绝不硬下绝对价；(c) **回填**：收盘后阶段一以 `use_cache=False` 对刚收盘交易日**强制重拉回填**，覆盖形成中 bar 为终态。盘口 tick（`option_chain.bid/ask`、`option_chain.last`、premium）是**某时刻真实快照**，仅用于盘中实时选腿 / 定价，不得替代日线 `close` 作历史绝对价基准。
- **实时数据（盘口 tick / 快照）分类**：实时数据分两类处理——(a) **瞬时盘口 tick**（`option_chain.bid/ask/last`、live premium、live IV）：盘中实时选腿 / 定价 / 盘口检查（#1）用之，纯瞬时、**不落日线类业务表**，扫描结束即弃；(b) **需留痕的实时值**：以**快照表 + `snapshot_time`（YYYY-MM-DD HH:MM:SS）**方式落库（范例 `option_iv`），用于复盘 / 审计 / 跨日比对，且**不与日终定稿行互相覆盖**——快照按 `snapshot_time` upsert、日线按 `pull_date`/`trade_date` upsert，两套主键互不干涉。若日后还需保留"扫描时刻盘口快照"，应**单开快照表**（如 `option_quote_snapshot`），禁止写回 `option_chain` 日终行。
- **复权锚定（后复权序列的时点依赖）**：`index_daily` 的后复权**绝对水平**不是 `(index_code, trade_date)` 的唯一事实——它依赖「复权锚定日（拉取日）」：锚定日不同（期间发生换月），历史后复权**水平**会重算而漂移（见下方实证）。但**后复权是乘性平移、保值收益率**：同一连贯拉取内任意两日之比 = 真实收益率，与锚定日无关。本表**仅用于相对指标**（收益率 / ADX / 区间位置），故锚漂移对其**无实质影响**；只有"拿后复权绝对价当价格"才会出错（已被"价格口径两分"铁律禁止）。处理：(a) 落库存**服务端后复权价 + `adj_ref_date`**（锚定日标记），弃用原始价 / 调整因子方案——tbpy `QuoteFlag` 仅 `RolloverBackWard` 一个复权枚举、无独立"原始价" flag（原始价需 `flag=None` 额外拉取，且对相对指标无益），故只拉一次 `RolloverBackWard` 即可；(b) 相对指标须在**同一 `adj_ref_date` 窗口**内计算，切勿跨不同锚定日的行混算（按批同锚天然避免）；(c) 不复权表（`contract_daily` / `underlying_spot` / `option_chain` 的 OHLC）是真实成交价、不随锚定日变，无此问题。（**实证**：本机 `strategies/sell_option/sell_option/data/daily.db` 的 `index_daily` 表中，`m9888.DCE` 在 `2026-09-30` / `10-08` / `10-09` 三次拉取的 298 个共同历史日，后复权收盘价**完全一致**——间隔内无换月事件，印证"水平漂移是事件驱动、非每拉必变"；即便有换月导致水平漂移，相对指标仍与锚无关。）
