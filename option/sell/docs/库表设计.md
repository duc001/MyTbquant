# option.sell 库表设计（v2）

> 配套 `docs/需求文档.md` §六/§七。本系统**数据驱动**，库表是地基：先定 schema，再写三阶段流水线（拉取 → 检查 → 报表）与策略逻辑。
> 设计原则：
> 1. **离线分析定位（总纲，2026-10-16 定）**：本系统是**离线分析系统，不是实时交易系统**——阶段一按日 / 按批**预取**数据 → 阶段二质检 → 阶段三产出**候选清单** → **人工执行**。故**不追求实时**：库里的一切行情数据都是**日线终态**（含 IV，见 §3.4），是**分析的输入本身**（不是"过期数据"）；分析结论须**如实标注数据日期**（一律 `bar_date`）；执行价与分析价的偏差**可接受**，执行前人工复核即可；数据日期落后只作**陈旧标注（STALE）**，不直接淘汰候选。派生口径见原则 3 / 4。
> 2. **业务数据**与**控制面**分离（逻辑上）：二者同处一个库文件 `option.db`，但用**不同的表**区分——业务数据表（§三）与控制面表（§二）互不混写，权限 / 生命周期也不同。
> 3. **价格口径两分**（承接需求文档 §二.1）：连续指数合约日线用**后复权**，仅供相对指标；合约（期货日线）/ 权利金用**不复权**，供一切绝对价。混用即缺陷。**绝对价一律取日线 `close`**（取哪一列见原则 4）。
> 4. **不取 tick / 全库日线化**（2026-10-17 更新）：**本系统不落任何 tick 源数据**；业务表**一律**按 `bar_date`（数据日期 / 交易日）分区 / 建索引——`option_iv` 已由「时点快照档」改为**日线档**（见 §3.4，openvlab 有历史 ATM IV 序列），故**本库不存在 tick / 快照档业务表**。离线分析的价格基准＝**日线终态 `close`**（可复现、无 60s 限流、无"行情源不在线"问题）；盘口 `bid`/`ask` 只能来自 `get_current_tick`，而它只在交易时段有值、盘后必然为空，且"无报价＝不可交易"本就该淘汰——故**不建盘口表、不做 #1 盘口价差**（以日线流动性代理 `volume` / `oi` / 最后成交日替代）。IV 与 greeks 由 openvlab 公开 HTTP 接口供给（与 tbpy tick 无关），见 §3.4 与 §3.3 注。
> 5. **命名规范**：全系统**单一库文件** `option.db`（不再一表一库）；**表名**一律**两词以上**且**与 v1 严格区分**（v1 用单词名如 `spot`/`iv`/`position`/`capital`，v2 改为 `option_info`/`option_daily`/`option_iv`/`account_position`/（账户资金不入库，见 §3.6）``trading_calendar`/`main_contract_daily`/`contract_daily` 等）；**"期权链"不是表名**——链是 `option_info` 的查询结果，`d06_option_chain.py` 是取数单元（见 §2.7）；字段须定义清楚（口径 / 单位 / 来源）。
> 6. **可拉尽拉**：凡是数据源能取到的字段——即使当前策略暂未使用——也**一律落库存储**，不得因"暂时不用"而丢弃（避免日后分析时无数据）。
> 7. 旧 `strategies/sell_option/` 的表结构**不沿用**，本文件为全新首稿。

## 二、控制面（库：option.db）

> 控制面 7 张表与业务数据同库（见 §一），但逻辑隔离、互不混写（设计原则 2）。判定口径＝**非行情数据**（无 `bar_date` 时序、无终态语义），而非"谁写入的"——既可来自 manual / 系统生成，也可来自外部接口的**元数据**接口（如 `get_instrument`）。分三类职责：**配置 / 声明**（`data_storage_rule`、`global_config`、`future_info`）、**运行态**（`data_state_check` 状态登记 + `data_pull_detail` 拉取明细流水）、**静态参考**（`trading_calendar` 交易日历、`option_info` 期权合约清单，存在即终 / 随上市·摘牌滚动，见 §2.6 / §2.7）。

### 2.1 global_config（中文名「全局配置表」，KV 表）

- **用途**：系统级 KV 配置——库路径（`path.db`）、**策略账户**（`account.strategy_id`）等已 seed 的开关；并预留 `source` / `schedule` / `gate` / `budget` / `mode` 等**配置域**（设计确认、待对应消费代码落地后再 seed，**不预置臆测默认值**，见下）。阶段二 / 三只读消费。
- **数据源**：**manual**（手工维护 / 启动加载），非外部行情拉取。
- **抽取方法**：初始化时写入或 `UPSERT`；以 `key` 为主键，不加自增 id（见 §四）。

```sql
CREATE TABLE global_config (
    "group"     TEXT,              -- 组/分组（account/budget/source/schedule/gate/mode/notify/path/threshold）
    key         TEXT,              -- 组内的键名（如 strategy_id / max_risk_degree）
    value       TEXT,              -- 配置值
    remark      TEXT,              -- 说明
    status      INTEGER DEFAULT 1, -- 1=可用/有效 / 0=不可用/无效（停用该配置）
    create_time TEXT,              -- 创建时间 YYYY-MM-DD HH:MM:SS
    update_time TEXT               -- 最后更新时间 YYYY-MM-DD HH:MM:SS
    , PRIMARY KEY ("group", key)   -- (group,key) 共同决定唯一 value；同组可多行（如多个账号）
);
```
> KV 配置表以业务复合键 **`(group, key)`** 为主键，**不加自增 id**；`group`＝组 / 分组，同组可多行（如 `account` 组下多个账号）。下方 `budget.*` / `account.*` 表中，点号前为 `group`、点号后为 `key`。

**本表不硬编码默认配置（config 不写在代码里）**：表结构由 `schema.apply_schema()` 统一创建与迁移（启动时建好），管理模块 `global_config.py` 只提供 `read()` 查询；无外部拉取源故无 `fetch()`，也不设写入方法（配置由人工 / 外部直接维护入库）。不预填任何默认行，表初始为空。校验方法 `check()` / `REQUIRED_KEYS` 待出现**真实必填配置项**后再补（当前无必填项，不做"永远 normal"的空校验）。

> **管理模块通用约定**：每张表的 fetcher 只直接读写**自己的**表；需写别张表（如回写 `data_state_check` 汇总表）一律调用对方管理类的方法，不跨表直接操作 SQL；建表/迁表属 schema 职责，由 `schema.py` 在启动时统一完成，fetcher 不做。

> 设计确认的**配置域**（`budget` 资金预算 / `source` 数据源 / `schedule` 预取 / `gate` 门禁 / `mode` 离线 / `path` 库路径）均为预留，**不预置臆测默认值**；`budget.*` 数值属策略参数，待对应消费代码落地、数值真正确定后再写。

> **为何预算不放在 `account_capital`**：账户资金是**事实**（券商给的、每日变、取不到须判 MISSING）；
> 预算是**参数**（我方自定、少变、随时可调）。混表有两个后果：① 阶段二会拿"新鲜度 / 终态"去校验一个
> **根本不是数据**的东西；② 参数改动会污染每日资金快照序列（同一 `pull_date` 出现不同预算）。故事实进
> **账户资金 JSON（不入库）**、参数进本表，二者只在报表侧**关联比对**。

### 2.2 data_storage_rule（数据存储规则表）

- **用途（表名 `data_storage_rule`，中文名「数据存储规则表」）**：阶段零**声明性配置**——登记"**每张需拉取的数据表**（取数单元，= 全部业务表 + 由接口拉取的控制面静态参考表如 `option_info`）该从哪取、主源是谁、基础窗口与口径标记（`date_type` 等）"。它本身不落业务数据，是阶段一 / 二 / 三读取配置的**声明入口**。**配置与逻辑分离**：本表只提供**配置参数与分类标记**，并不承载核对规则本身；"应有条数怎么算、何时算终态、什么算正常 / 异常"这些**逻辑由检查程序依据本表的标记实现**，结果写入 `data_state_check`（见 §2.3）。本表是"声明"，检查程序是"规则引擎"。
  - **粒度**：一行 = 一个取数单元（以 `table_ref` 标识），即**一表一取数单元**（如 `main_contract_daily` 一张表、一种后复权取数方式，覆盖 `future_info` 中全部 `main_index_symbol`（活跃主连））；数据源记于 `data_source` 单列（不设降级列）。
  - **字段语义**：
    - `table_ref`：落到哪张物理表；同时充当**取数单元唯一键**，以及与 `data_state_check` 对账的连接键（`UNIQUE`）。
    - `table_name`：表名（人读，区别于 `table_ref` 的物理表引用；如 '主连后复权日线'）。
    - `date_type`：数据类型的**元数据**（沿用 tbpy 语义名 `bar` / `static`，不翻译）。**`tick` 档已于 2026-10-17 取消**：`option_iv` 归入 `bar` 档（openvlab 有历史 ATM IV 序列，见 §3.4），故**本库无时点 / 快照档业务表**（设计原则 4）。本表仅做分类标注，**下游各规则据此施管**：`bar`→日线终态判定按 `bar_date`（收盘后为终态、盘中为形成中，见 §五）；`static`→存在即终。`date_type` 与 `store_mode` 维度不同、不冲突。
    - `data_source`：主数据源（如 `tbpy`）。
    - `pull_method`：拉取方式（`post_close` / `intraday` / `event` / `low_freq`；`low_freq` 用于低频/静态单元如 `trading_calendar`）。**离线分析定位下**：默认 `post_close`（盘后/定时批量预取），`intraday` 仅表示"取数时点可能落在交易时段内"（**非实时循环**）——此时须按 §五 判"形成中 bar / 未定稿"。
    - `pull_count`：每次拉取的**回溯条数**，**按每标的计**（main_contract_daily=300 为整窗重拉；incremental_upsert 表仅取新 bar，`pull_count=1`；时点档/static 档留空）。
    - `store_mode`：落库模式，取值各对应一档数据：`incremental_upsert`→不复权档（如 `contract_daily` / `option_daily` / `option_iv`）/ `full_window_rewrite`→后复权档（如 `main_contract_daily`，整窗重写天然同锚）。**原 `append_snapshot`（时点快照档）已随 tick 档取消**（2026-10-17）。
    - `required_fields`：必填非空字段，字段级缺失检。
    - `status`：状态（1=有效/0=无效；有效=纳入应有效验，无效=旁路不拉不校验、不报错）。
  - **三阶段驱动（配置供程序消费）**：①阶段一按本表逐行（启用态）拉取并落库；②阶段二**检查程序**据 `date_type` 等标记实现核对——bar 档"应有条数" = `[bar_start_date, bar_end_date]` 区间内**实际交易日数**（依 `trading_calendar` 剔除节假日）× `future_info` 中全部 **`main_index_symbol` 实体数**——**不得用区间自然日跨度推算**（节假日无 bar 数据）；终态与正常 / 异常判定同样由检查程序按 `date_type` 实现（语义见 §2.3 四态 / §五）；③阶段三门控据 `data_state_check` 判定放行：**仅当 `status='normal'` 且 `bar_end_date` 已覆盖到所需交易日**才放行，否则（区间未覆盖 / `init` / `fetching` / `abnormal`）阻塞或等待。
  - **与 `data_state_check` 的关系（配置面 vs 状态面）**：两表经 `table_ref` 关联。`data_storage_rule` 是**被监控表的声明**（配置面）；`data_state_check` 是**检查程序依据本表声明、对每张表核对后的逐表状态登记**（状态面）。本表不定义"应有"的推导公式，只给出声明性参数（`date_type` / `pull_count` / `future_info` 关联等），具体"应有条数 / 终态 / 正常·异常判定"由检查程序实现，结果写回 `data_state_check`（status / last_detail_id 等）；对不上的即数据异常（见 §2.3 四态）。
  - **单一声明源（非规则源）**：§三 各表"用途 / 数据源 / 抽取方法"仅为人读说明，其**声明性取值**（数据源 / 窗口 / 写模式）以本表为准，冲突优先本表；但**核对规则（应有推导、终态与正常异常判定）不在本表**，由检查程序实现（见 §2.3 / §五）。

- **数据源 / 维护**：**manual**（设计期固化），随 schema 设计写入、状态 `status`；系统启动加载为期望基线。

- **一致性约束**：各业务表须按 §四 在其上建立 `UNIQUE` 约束以保证去重（本表不另存去重键）；`store_mode` / `date_type` 取值须与对应业务表实际取数 / 存储方式一致。

```sql
CREATE TABLE data_storage_rule (
    id INTEGER PRIMARY KEY AUTOINCREMENT,            -- 自增主键
    table_ref    TEXT UNIQUE,   -- 物理表引用（取数单元唯一键 + 对账连接键）
    table_name   TEXT,          -- 表名（人读）
    date_type    TEXT,          -- 数据类型
    data_source  TEXT,          -- 主数据源
    pull_method  TEXT,          -- 拉取方式
    pull_count   INTEGER,       -- 每标的回溯条数（时点档/static 档留空）
    store_mode   TEXT,          -- 落库模式
    required_fields TEXT,       -- 必填非空字段清单（逗号分隔列名）
    status       INTEGER DEFAULT 1,  -- 状态（1=有效/0=无效）
    remark       TEXT,          -- 备注
    create_time  TEXT,          -- 创建时间
    update_time  TEXT           -- 更新时间
);
```

### 2.3 data_state_check（数据状态核对表）

- **用途（表名 `data_state_check`，中文名「数据状态核对表」）**：`data_storage_rule` 所登记各取数单元的**逐表运行状态登记**（按 `table_ref` 1:1 对账）。每行记录该表**当前已就绪的数据区间 `[bar_start_date, bar_end_date]`**、**当前状态**（`status`，四态见字段语义）与**最近一次明细引用**（`last_detail_id` → `data_pull_detail.id`）。回答"这张表的数据是否准备完毕且正确"：`normal` 放行 / `abnormal` 阻塞 + 报警 / `init`·`fetching` 等待。本身是**状态面**：只沉淀核对结论，**不存明细**——拉取日期、实拉条数、`err_msg` 等一律记入 `data_pull_detail`（见 §2.4）；核对规则由检查程序实现（见 §2.2）。
  - **字段语义**：
    - `id`：自增主键，仅标识写入先后。
    - `table_ref`：本表主键（= `data_storage_rule.table_ref`，两表经此 1:1 对账），`UNIQUE`。
    - `bar_start_date`：本状态覆盖的数据**起始交易日**（归属日 `YYYY-MM-DD`）；对 bar 档即 bar 区间起点，对 static 档表示其数据覆盖的日期范围（或留空，由完整性判定，见 §五）。
    - `bar_end_date`：本状态覆盖的数据**结束交易日**（通常为最新已就绪 `bar_date`）；与 `bar_start_date` 共同标识"已核对的是哪段数据"，而非拉取动作日。
    - `status`：**四态状态机**（简化，驱动全部门控）。取值：`init`（初始化：已登记、待拉取）→ `fetching`（拉取中：含校验中、盘中形成中 bar 尚未定稿，视为"尚未准备完毕"）→ 终局之一：`normal`（数据正常：拉取完成且校验通过、终态、**可放行**）/ `abnormal`（数据异常：缺数据 / 脏数据 / 校验不通过，**阻塞 + 报警**）。门控口径：仅 `normal` 放行；`init` / `fetching` 等待；`abnormal` 阻塞。
    - `last_detail_id`：指向 `data_pull_detail.id` 的**最近一次明细引用**；检查程序每轮动作后 upsert 本表并把本次明细行 `id` 写入此列，状态表借此关联到"当前结论来自哪次拉取"，错误 / 计数等明细全部从 `data_pull_detail` 读取，本表不存 `err_msg`。
  - **与 `data_storage_rule` 的关系（状态面）**：本表给**核对结论**（status / last_detail_id 指针），`data_storage_rule` 给"声明"（被监控表 + 参数）。"应有"推导与"正常 / 异常"判定由**检查程序**按 `date_type` 实现（bar：区间内实际交易日数（`trading_calendar` 剔除节假日）× `future_info` 全部 `main_index_symbol` 实体数，勿用自然日跨度；static：完整性。**无 tick 档**，见 §2.2 `date_type`），对不上的即 `abnormal`（见 §2.3 四态 / §五）；检查程序内部比对"应有 vs 实有"后只暴露结论（状态 + 明细指针，错误明细在 `data_pull_detail`），不持久化实有计数。
  - **不使用外键**：`data_state_check` ↔ `data_storage_rule` 仅以业务键 `table_ref` 软引用（1:1），`data_state_check.last_detail_id` ↔ `data_pull_detail.id` 亦为软引用；`id` 仅表写入先后、随 upsert 会变，挂外键会悬空，故两表（及对账明细）以业务键 / id 软关联、无需外键。

- **数据源 / 写入**：**系统生成（检查程序产出）**——阶段一创建行置 `init`、启动拉取置 `fetching`，阶段二（校验）完成置 `normal` / `abnormal`；异常时检查程序可重试，每次重试作为新动作行记入 `data_pull_detail`（以 `pull_time` 区分），状态表仅以 `table_ref` upsert 刷新当前态与 `last_detail_id`；每轮预取 / 校验后 upsert。

```sql
CREATE TABLE data_state_check (
    id INTEGER PRIMARY KEY AUTOINCREMENT,   -- 自增主键
    table_ref TEXT UNIQUE,                  -- 本表主键（= data_storage_rule.table_ref，1:1 对账）
    bar_start_date TEXT,                    -- 覆盖的数据起始交易日
    bar_end_date TEXT,                      -- 覆盖的数据结束交易日（最新已就绪 bar_date）
    status    TEXT,                         -- 四态状态机：init→fetching→(normal|abnormal)；仅 normal 放行
    last_detail_id INTEGER,                 -- 最近一次明细引用（→ data_pull_detail.id）
    remark TEXT,                            -- 备注
    create_time TEXT, update_time TEXT      -- 创建/更新时间
);
```

### 2.4 data_pull_detail（数据拉取明细表）

- **用途（表名 `data_pull_detail`，中文名「数据拉取明细表」）**：每次拉取 / 核对动作的**流水明细**，与 `data_state_check`（状态登记，每表一行）互补。后者只存"当前状态"，本表存"每次动作发生了什么"——拉取日期 (`pull_date`)、覆盖的数据区间、应有 / 实有计数、明细错误、拉取时间 (`pull_time`)。它是 `data_state_check` 的**审计轨迹**：某张表今天拉了几次、每次拉到多少、为何失败，全在本表可追溯；状态表只沉淀最终结论。
  - **粒度**：一行 = 一次拉取 / 核对动作（`table_ref` + `pull_time` 唯一确定）；同一 `table_ref` 可有多行（每日多次拉取 / 重试均留痕）。
  - **字段语义**：
    - `id`：自增主键。
    - `table_ref`：连接键（= `data_storage_rule.table_ref`），与状态表对账。
    - `pull_date`：**拉取日期**（`YYYY-MM-DD`，本次拉取动作发生的日期，动作日）——区别于业务表数据归属日 `bar_date`，也区别于状态表的数据就绪区间。
    - `pull_time`：本次拉取**完整时间戳**（`YYYY-MM-DD HH:MM:SS`，动作时刻）；`pull_date` 为其日期部分，本列用于排序 / 定位每次拉取动作，取代原 `fetch_at` / `validate_at` 的"动作时间"角色。
    - `bar_start_date` / `bar_end_date`：本次拉取覆盖的数据区间（对 bar 档即 bar 区间；对 static 档表示其数据覆盖的日期范围，或留空由完整性判定，见 §五）。
    - `expected_n`：检查程序推导的**应有条数**（审计用）；算法：区间内**实际交易日数**（依 `trading_calendar.is_trading_day=1` 剔除节假日）× 活跃实体数，**不得用 `[bar_start_date,bar_end_date]` 自然日跨度推算**（节假日无 bar 数据）。
    - `actual_n`：本次**实拉条数**。
    - `status`：本次动作结果的**状态快照**（init / fetching / normal / abnormal），与状态表 `status` 同域。
    - `err_msg`：本次**明细错误的摘要**（缺失字段类别 / 异常品种计数 + 少量样本 / 失败原因）；**硬约束：不得逐条罗列全部异常项**——异常品种 / 行等列表过长时仅保留前若干样本并附"…共 M 条"计数，保持单行轻量、可消费；逐条排查由业务表反查，不塞入本字段。
    - `remark`：备注。
    - `create_time` / `update_time`：创建 / 更新时间。
  - **与 `data_state_check` 关系（流水 vs 状态）**：状态表（§2.3）每表一行沉淀"当前是否 ready"，本表每表多次一行留痕（粒度见上）。检查程序每轮拉取 / 校验后**双写**：既 upsert 状态表（`table_ref` 行，刷新 `status` / 数据区间 / `last_detail_id`），也 insert 本表（新动作行，以 `pull_time` 唯一区分）。

- **数据源 / 写入**：**系统生成（检查程序产出）**——每轮拉取 / 校验动作完成（或失败）后 insert 一行。

```sql
CREATE TABLE data_pull_detail (
    id INTEGER PRIMARY KEY AUTOINCREMENT,   -- 自增主键
    table_ref TEXT,                         -- 连接键（= data_storage_rule.table_ref）
    pull_date TEXT,                         -- 拉取日期（动作发生日，非 bar 归属日 bar_date）
    pull_time TEXT,                         -- 拉取完整时间戳（YYYY-MM-DD HH:MM:SS，动作时刻）
    bar_start_date TEXT,                    -- 本次覆盖数据起始交易日
    bar_end_date TEXT,                      -- 本次覆盖数据结束交易日
    expected_n INTEGER,                     -- 应有条数（按交易日历剔除节假日后 × 活跃实体数，审计用）
    actual_n INTEGER,                       -- 实拉条数
    status    TEXT,                         -- 本次动作结果状态快照（init/fetching/normal/abnormal）
    err_msg     TEXT,                       -- 本次明细错误（摘要化，截断勿逐条罗列）
    remark TEXT,                            -- 备注
    create_time TEXT, update_time TEXT,     -- 创建/更新时间
    UNIQUE (table_ref, pull_time)           -- 防同批次重复 upsert
);
```

### 2.5 future_info（期货品种信息表）

- **用途**：**期货品种级**静态参数——品种中文名 / 交易所 / 现价 / 乘数 / 保证金金额（单腿 / 实际占用）/ 组合优惠，以及期货·期权 C/P 的 **symbol 格式模板**（`fut_symbol_template` / `opt_call_template` / `opt_put_template`，取数拼接合约用）+ 主力指数**合约**（`main_index_symbol`，后复权主连，直接拉日线）；业务表经 `product_cd` 关联 `future_info.product_cd` 取数；单列不塞进 `global_config`。
- **粒度＝品种（47 行，固定、不滚动）**：本表只描述**期货品种**本身，**不描述单个合约**——期货合约代码可由 `fut_symbol_template` + 月份推导、同品种各月份合约**乘数一致**，故**不需要再建"期货合约信息表"**；
  （注：**最小变动价位并非全品种一致**——实测期权 ≠ 标的期货（m 期货 1.0 / 期权 0.5、i 0.5/0.1），故期权档位属性存于合约级 `option_info`，本表不存 `price_tick`；）
  **期权不同**：期权行权价阶梯 / 合约增减**不可推导、且逐月滚动**（m 当前 8 个月 310 个合约），故期权侧另立**合约级、滚动**的 `option_info`（§2.7）——二者层级不同正是"期货固定 / 期权滚动"的如实映射。
- **数据源**：`品种边界表.md`（本仓库内 markdown 权威源，47 品种；见 §二 开头职责划分）。本表即该文件的**结构化镜像**——取数加载器解析其【一、边界表数据】表格逐行填充，**字段严格对齐文件列**（见下；**唯一例外**：`margin_per_lot` / `actual_margin_per_lot` 两列由源的「万元」**×10000 归一为元**，全库金额统一为元，见 §四），非手工维护、非外部接口；旧 `config.py` 已删，取数以本文件为准。
- **补源 / 对账（2026-10-17 实测，openvlab 纯公开 HTTP JSON）**：`GET /api/product-exps` 一次返回全部 **79 个标的**的
  `symbol`(`OPT_DCE_M`) / `symbol_und`(`FUT_DCE_M`) / `exps[].expDate`(精确到期日) / `front_exp` /
  **`minMove` / `minMove_und`（期权 / 期货分别给最小变动价位）** / **`precision` / `precision_und`** /
  各到期月的**当日** `limit_up` / `limit_down`；`GET /api/symbol/{code}` 另给 `pricescale` / `minmov` /
  `session`(交易时段串) / `session_holidays`(该品种休市日) / `expiration_date`。
  实测 m：`minMove_und=1.0`、`minMove=0.5`、`precision=1` —— 再次印证"期权最小变动价位 ≠ 标的期货"。
  **用途＝对账与补缺**（发现镜像值过期 / 缺项时报警），**不自动覆盖**本表镜像值（权威源仍是 `品种边界表.md`）。
- **抽取方法**：初始化写入 / 维护；以 `product_cd` 为主键，不加自增 id。

```sql
CREATE TABLE future_info (
    product_cd        TEXT PRIMARY KEY,  -- 品种代码（含大小写，如 AP/rb/m）[文件主键]
    product_name      TEXT,             -- 品种中文名（苹果/螺纹钢）
    exchange          TEXT,             -- 交易所编码（SHFE/DCE/CZCE/GFEX）
    last_price        REAL,             -- 参考现价【边界表镜像值，非权威】——权威现价取 contract_daily 最新 bar_date 的 close
    multiplier        REAL,             -- 乘数（contract_unit；期权与标的期货一致，故期权也取本列）
    margin_per_lot    REAL,             -- 单腿保证金（元）= 现价 × 乘数 × 保证金率（load 时由源的万元 ×10000 归一为元，见 §四）
    actual_margin_per_lot REAL,         -- 实际占用（元/手）= 单腿保证金×组合优惠（同为元口径）
    combo_discount    REAL,             -- 组合优惠系数（DCE·GFEX ×0.20，其余 1.0）
    fut_symbol_template TEXT,           -- 期货 symbol 格式模板（非实盘月份，取数套格式用）
    main_index_symbol TEXT,             -- 主力指数合约（后复权主连，真实可用，直接拉日线，如 rb888.SHFE）
    opt_call_template TEXT,             -- 期权 C 格式模板（非实盘月份，取数套格式用）
    opt_put_template  TEXT,             -- 期权 P 格式模板（非实盘月份，取数套格式用）
    remark            TEXT
);
```

### 2.6 交易日历：trading_calendar

- **用途**：交易日历。驱动预取时机、终态判定、跨日老化、长假 / 破位提醒。
- **数据源**：**manual**（由本地 `manual_calendar` 逐日播种，已本地化，不再依赖 tbpy.is_holiday / 外部日历）。
- **对账备源（2026-10-17 实测，openvlab）**：`GET /api/holidays/{exchange}`（如 `DCE`）返回**逗号分隔的休市日串**，
  实测覆盖 **2023-01-01 ~ 2026-10-07**（含 2026 全年节假日）。纯公开 HTTP、无需 tbpy。
  用途＝**播种后的交叉校验**（本地 `manual_calendar` 与之一致性比对，不一致报警交人工裁决），**不自动改写**本地日历；
  另 `GET /api/symbol/{合约}` 的 `session_holidays` 可作**单品种**休市日核对。
- **抽取方法**：阶段一每日或低频预取 → 写入 `bar_date` + 衍生标志（月末 / 季末 / 年末 / 邻长假）→ `bar_date UNIQUE` 真 upsert；静态参考表，非逐日终态。

```sql
CREATE TABLE trading_calendar (
    id                    INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    bar_date            TEXT UNIQUE, -- 交易日 YYYY-MM-DD
    is_trading_day        INTEGER,  -- 1 交易日 / 0 非
    is_month_end          INTEGER,
    is_quarter_end        INTEGER,  -- [可拉尽拉]
    is_year_end           INTEGER,  -- [可拉尽拉]
    prev_bar_date       TEXT,    -- 上一交易日 [可拉尽拉]
    next_bar_date       TEXT,    -- 下一交易日 [可拉尽拉]
    pre_long_holiday_days   INTEGER,  -- 距前一长假天数
    post_long_holiday_days  INTEGER,  -- 距后一长假天数
    holiday_name          TEXT,    -- 临近长假名 [可拉尽拉]
    remark                TEXT
);
```

### 2.7 期权合约信息：option_info（静态参考）

> **实现状态**：本表与 `option_daily` **目前仅设计、代码未落地**（全库无 `CREATE TABLE` / `INSERT` / `SELECT`）；
> 期权侧现落库的是旧缓存表 `premium`、`iv_snapshot`，落地时收编。
> **归控制面的理由**：它是**合约元数据（清单 / 条款）**，不是行情数据——**无 `bar_date`、无时序、无终态语义**，
> 属"静态参考"；与品种级 `future_info`（§2.5）同属参考数据，仅**层级不同**（品种固定 vs 合约滚动）。
> 数据**由接口拉取**（非 manual），故仍纳入 `data_storage_rule` 取数契约（static 档，见 §2.2 注）。
> 分类改动：2026-10-16 由 §三 业务数据表移入 §二 控制面。

- **用途**：**期权合约清单 / 条款**（`symbol` 级静态参考表）。回答"现在有哪些期权合约、各自什么条款"——
  选腿枚举行权价档位、DTE 计算、symbol 解析校验皆以此表为准。
- **为何不并入 `future_info`（§2.5）**：`future_info` 是**品种级、固定**（47 行），期货合约可由模板 + 月份推导；
  期权**行权价阶梯不可推导、且逐月滚动**（m 当前 8 个标的月 / 310 合约）→ 必须**合约级 + 滚动维护**。
- **"期权链"不是表**：链＝`WHERE product_cd=? AND underlying_month=?` 查出的一批行（行权价 × C/P），
  是**查询结果**；`d06_option_chain.py` 是产出本表的**取数单元**。
- **数据源**：主源 **tbpy**——`get_symbols()` 过滤出期权 symbol + `get_instrument(symbol=…)` 补元数据。
  （工程注意：`get_symbols()` 返回约 **11.4 万**条，须在**隔离子进程 / 模块级持有**以避免析构时堆损坏。）
  备源 **openvlab** `/api/product-exps`（仅到期日）、**新浪**（仅主力月阶梯）**都不能独立建链**；
  全源失败 → 该品种断源、下游判 **MISSING**，不猜合约。
- **抽取方法**：日频增量——`get_symbols()` 比对新增 symbol → 逐个 `get_instrument()` 写入；
  `delisted_date` 已过即失效（**滚动闭环**）。`symbol` 为 `PRIMARY KEY`，**静态表不加自增 id**（§四）。

- **返回字段（`get_instrument` → `Instrument`，实测全量 10 个；样例 `m2611-C-3000.DCE`）**：

  | # | 返回字段 | 类型 / 实测值 | 落库 | 说明 |
  |---|---|---|---|---|
  | 1 | `symbol` | `str` `m2611-C-3000.DCE` | → `symbol`（PK） | 完整合约代码 |
  | 2 | `sec_id` | `str` `m2611-C-3000` | **不落** | ＝`symbol` 去交易所后缀，冗余 |
  | 3 | `sec_name` | `str` `豆粕期权m2611-C-3000` | → `sec_name` | 合约中文名（唯一人工可读字段） |
  | 4 | `exchange` | `str` `DCE` | **不落** | ＝`symbol` 后缀，且＝`future_info.exchange` |
  | 5 | `listed_date` | `datetime` `2025-11-17 00:00:00` | → `listed_date` | 格式化为 `YYYY-MM-DD`；识别新挂合约 |
  | 6 | `delisted_date` | `datetime` `2026-10-23 00:00:00` | → `delisted_date` | 期权最后交易日＝**DTE 基准**；过期即失效 |
  | 7 | `price_tick` | `float` `0.5` | → `price_tick` | **期权 ≠ 标的期货**（m 1.0/0.5、i 0.5/0.1），必须本表存 |
  | 8 | `contract_unit` | `float` `10` | **不落** | 实测与标的期货一致 → 取 `future_info.multiplier`（单一事实来源） |
  | 9 | `big_point_value` | `float` `1.0` | **不落** | 7/7 样本恒为 1.0，零信息量（金额＝价 × 1 × `contract_unit`） |
  | 10 | `deal_times` | `str` `'\|21:00-23:00;09:00-10:15;10:30-11:30;13:30-15:00;\|\|\|\|\|'` | → `deal_times` | 交易时段串（`\|` 起、`;` 分 8 段：夜盘 + 3 段日盘 + 4 空段）；**`session_hours` 交叉校验源**（见下） |

    SHFE `cu` 本地 21:00-**02:30** vs tbpy 21:00-**01:00**（铜实际收 01:00，au/ag 才是 02:30）；
    CZCE 本地 21:00-**23:30** vs tbpy 21:00-**23:00**（郑商实际收 23:00）。
    故保留该列作**自动对账源**，而非"已本地化故丢弃"。

  | `cu2611C80000.SHFE` | 期权 | 2026-10-26 | 5 | 2.0 |
  | `CF701C15000.CZCE` | 期权 | 2026-12-11 | 5 | 1.0 |

  1. **期权 `delisted_date` ≠ 标的期货**（m2611：10-23 vs 11-13，早 21 天）→ 必须**合约级自存**，
     不可由标的月反推（`x4_expiry` 的 DTE 基准）。
  2. **`price_tick` 期权 ≠ 标的期货**（m 1.0/0.5、i 0.5/0.1）→ **必须本表存**，不能取 `future_info`。
  3. **`contract_unit` 与标的期货一致**（10/10、100/100、5/5）→ 单一事实来源在 `future_info.multiplier`，
     **本表不存**（避免两处维护）。
  4. **symbol 格式随交易所而异**：DCE `m2611-C-3000`、SHFE `cu2611C80000`、CZCE `CF701C15000`
     （**月份 3 位**，需按年代补全为 4 位，见 D07）→ 故 `product_cd` / `underlying_month` / `cp` / `strike`
     **解析后落库**，下游不再各自解析。
  5. **行权价阶梯不可推导**（故需实测取回）：m2611 实测 2500…3800 共 **26 档**（C/P 各 26），且**档距分段**
     （2500→2600 为 100、2600 起为 50）→ 无法按固定档距推算，只能来自 `get_symbols()`。

```sql
CREATE TABLE option_info (              -- 静态参考表：业务键为 PRIMARY KEY，不加自增 id（§四）
    symbol            TEXT PRIMARY KEY,  -- 期权合约代码 m2611-C-3000.DCE / cu2611C80000.SHFE
    product_cd        TEXT,  -- 标的品种码（→ future_info.product_cd），如 m
    underlying_symbol TEXT,  -- 标的期货合约 m2611.DCE（→ contract_daily.symbol）
    underlying_month  TEXT,  -- 标的月 4 位 '2611'（CZCE 3 位按年代补全）

    listed_date       TEXT,  -- 上市日 YYYY-MM-DD ← Instrument.listed_date
    delisted_date     TEXT,  -- 最后交易日 YYYY-MM-DD ← Instrument.delisted_date（DTE 基准；过期即失效）
    price_tick        REAL,  -- 最小变动价位 ← Instrument.price_tick（与标的期货不同，必须本表存）
    sec_name          TEXT,  -- 合约中文名 豆粕期权m2611-C-3000 ← Instrument.sec_name
    deal_times        TEXT,  -- 交易时段串 ← Instrument.deal_times（session_hours 交叉校验源）
    UNIQUE (symbol)
);
```

### 3.1 指数合约日线：main_contract_daily

- **用途**：**主连连续合约后复权日线**（文档中常称"指数"，888 后缀，如 `m9888.DCE` / `rb888.SHFE` / `IF888.CFFEX`），服务端 `RolloverBackWard` 换月后复权、抹平主力换月跳空。**仅服务相对指标**（收益率 / 波动率 / 趋势 / ADX / 区间位置），绝不用于任何绝对价（价格口径两分铁律，见设计原则 3 / 需求文档 §二.1）。
- **数据源**：
  - **主源（唯一已实现）**：`tbpy`——`tbpy.get_history_n(symbol, "1d", count, fields, flag=tbpy.QuoteFlag.RolloverBackWard)` 取**服务端后复权**日线，属**三阶段驱动**的「拉取」阶段（拉取 → 检查 → 生成报表，由 §2.2 `data_storage_rule` 驱动）。
  - **返回字段**（tbpy 对连续合约返回 `time`/`open`/`high`/`low`/`close`/`volume`/`position`/`rollover` 八项）：本表**全取**——`time`（datetime）→ 格式化为 `bar_date`(`YYYY-MM-DD`)；`open`/`high`/`low`/`close`（后复权）→ 对应列；`volume`（手）→ `volume`；`position`（持仓量，手）→ **`oi`**（列名统一用 `oi`，不用 `position`，原因见 §3.3 命名对照）；`rollover`（后复权调整因子）→ `rollover`。`pre_close`/`amount`（非 tbpy 字段、对相对指标无用）与 `turnover`（换手率）/`vwap`（均价，股票口径）**已从本表移除**。
  - **为何只取后复权**：`QuoteFlag` 仅 `RolloverBackWard` 一个复权枚举、无独立「原始价」flag（原始价须 `flag=None` 另拉、且本表不需要），故一次拉取即够；原始价由 `contract_daily` 不复权表承载。
  - **备选**：**新浪**（§七 Q1 开放项，待验证）。
- **字段语义**（参考 §2.2 `data_storage_rule` 字段语义格式）：
  - `id`：自增主键，仅标识数据写入先后（技术键，非业务键）。
  - `main_symbol`：主连连续合约代码，本表业务键；对应 `future_info` 全部 `main_index_symbol`；落库以该键 `full_window_rewrite` 整段全量重写。
  - `bar_date`：交易日，`YYYY-MM-DD`。
  - `open` / `high` / `low` / `close`：后复权 OHLC（换月后复权）。
  - `volume`：成交量（手）。
  - `oi`：持仓量（手，← tbpy `position` 字段；主连对应前月合约的未平仓合约数；期货持仓量信号，非相对指标必需、按需使用）。列名不用 `position`，以避与"账户持仓"（`account_position` / `tbpy.Position`）一名两义。
  - `rollover`：后复权调整因子（换月系数）；本批拉取窗口内恒定、发生换月时跳变，用于复权血缘与换月观测，相对指标计算不依赖。
  - 约束：`UNIQUE(main_symbol, bar_date)`，同标的同交易日唯一，防意外重复插入。
  - **抽取方法**：阶段一每日盘后据 `data_storage_rule`（`table_ref='main_contract_daily'`）预取 → `get_history_n(..., count=pull_count, fields, flag=RolloverBackWard)` 拉后复权 OHLC + 持仓量/复权因子。`pull_count` 默认 **300**（≈1.2 年日线，覆盖 ADX / 波动率 / 区间百分位回看）。**落库 = `store_mode='full_window_rewrite'`**：整窗拉取（非仅拉新 bar），事务内先 DELETE 该标的历史窗口、再 INSERT 本批全窗，幂等、同日重拉命中缓存跳过；后复权须单锚一致，增量 append 会混新旧锚、换月后相对指标算错（机理见 §五 复权锚定）。`date_type='bar'` 派生「收盘后为终态」。对照：不复权表 `contract_daily` / `option_daily` 用 `store_mode='incremental_upsert'` 追加新 bar。后复权表不可增量、须整窗重写。

```sql
CREATE TABLE main_contract_daily (
    id INTEGER PRIMARY KEY AUTOINCREMENT,            -- 自增主键，标识数据写入先后
    main_symbol   TEXT,          -- 主连连续合约代码，如 m9888.DCE / rb888.SHFE / IF888.CFFEX
    bar_date   TEXT,          -- 交易日 YYYY-MM-DD
    open         REAL,          -- 开盘价（后复权，换月后复权）
    high         REAL,          -- 最高价（后复权）
    low          REAL,          -- 最低价（后复权）
    close        REAL,          -- 收盘价（后复权）
    volume       REAL,          -- 成交量（手）
    oi           REAL,          -- 持仓量（手，← tbpy position；不用 position 列名以免与账户持仓混淆）
    rollover     REAL,          -- 后复权调整因子（换月系数）
    UNIQUE (main_symbol, bar_date)
);
```

- **录入示例**（`store_mode='full_window_rewrite'`，事务内整窗重写，幂等）：
  ```python
  def store_main_contract_daily(conn, symbol, bars):
      # bars: get_history_n 返回、并经 time(datetime)→bar_date(YYYY-MM-DD) 格式化的全窗行
      with conn:  # 单事务：先删该标的历史窗口，再插本批全窗
          conn.execute("DELETE FROM main_contract_daily WHERE main_symbol = ?", (symbol,))
          conn.executemany(
              "INSERT INTO main_contract_daily "
              "(main_symbol, bar_date, open, high, low, close, volume, oi, rollover) "
              "VALUES (:main_symbol, :bar_date, :open, :high, :low, :close, :volume, :oi, :rollover)",
              bars,
          )
  # 同日重拉：DELETE 已清空该标的历史窗口后 INSERT 本批全窗 → 结果一致（幂等）
  ```

### 3.2 合约日线：contract_daily

- **用途**：**月度期货合约日线（不复权）**。承载**标的绝对价**需求——现价、行权价、保证金、安全垫、封顶、肥瘦判定；**权利金（期权自身价格）存于 `option_daily`，本表提供其估值所需的标的期货价**；与 `main_contract_daily`（后复权、相对指标）严格分流，混用即缺陷（价格口径两分铁律）。
  **离线分析口径**：标的"现价"＝本表**最新 `bar_date` 行的 `close`**（终态、可复现），**不取 tick**；报告须标注该 `bar_date`。
- **数据源**：
  - **主源（唯一已实现）**：`tbpy`——`get_history_n(symbol, "1d", count, flag=QuoteFlag.Null)` 取**具体合约**的**不复权（原始）**日线，`symbol` 为月合约代码（如 `m2601.DCE`）；属「拉取 → 检查 → 生成报表」三阶段驱动的「拉取」阶段（由 §2.2 `data_storage_rule` 驱动）。
  - **返回字段**（`get_history_n(symbol, '1d', …)` 实测 2026-10-16，`m2611.DCE`）：
    **有值**＝`open` / `high` / `low` / `close` / `volume` / `position`(持仓量) / `time`；
    **实测空数组**＝`turn_over`(成交额) / `pre_close`(昨收) / `settle`(结算价) / `limit_up` / `limit_down` / `avg_price` / `open_int`（后者是对象属性名，fields 里须写 `position`）。
    故 tbpy 侧本表只填 `symbol` + 派生 `product_cd`/`expire` + `bar_date`(←`time`) + OHLC + `volume` + `oi`(←`position`)。
  - **补源 openvlab `/api/history`（2026-10-17 实测，纯公开 HTTP JSON、无需登录）**：
    `GET /api/history?symbol=M2611&resolution=1D&from={unix}&to={unix}` → **222 条日线**（≈1 年，起点 2025-11-17），
    字段 `ts_code / trade_date / pre_close / pre_settle / open / high / low / close / settle / change1 / change2 /
    vol / amount / oi / oi_chg`——**tbpy 取不到的 `pre_close` / `settle` / `amount`，加上 `pre_settle` / `oi_chg`，
    openvlab 全部有值**（实测 `M2611` 2025-11-17 行：`pre_settle=2957.0`、`settle=2951.0`、`amount=37990.17`）。
    **坑**：`resolution` **必须 `1D`（大写 D）**，`1d` / `D` 静默返回 `data:[]`。
    故本表**补设** `pre_close` / `settle` / `amount` / `pre_settle` / `oi_chg` 五列，由**补源**填充，
    并以 `data_source` 列标记该行来源（避免把两源数据混当同源真值）。
  - **为何不复权（flag=None）**：本表服务绝对价，须是真实成交原始价，故 `flag=QuoteFlag.Null`（无复权）；相对指标一侧由 `main_contract_daily`（`RolloverBackWard` 后复权）承载，两表字段口径不可混。
  - **备选**：**新浪(sina)**（§七 Q1 开放项，待验证）。
- **字段语义**（参考 §2.2 `data_storage_rule` 字段语义格式）：
  - `id`：自增主键，仅标识数据写入先后（技术键，非业务键）。
  - `symbol`：月合约代码（如 `m2601.DCE`），本表业务键；对应 `future_info` 全部合约。
  - `product_cd`：标的代码，由 `symbol` 解析派生（合约代码含标的与到期月）。
  - `expire`：到期月 `YYYY-MM`，由 `symbol` 解析派生。
  - `bar_date`：交易日，`YYYY-MM-DD`。
  - `open` / `high` / `low` / `close`：不复权 OHLC（真实成交价）。
  - `volume`：成交量（手）。
  - `oi`：持仓量（手，← tbpy `position` 字段）。
  - **tbpy 取不到、但 openvlab 补源有值（落本表）**：`pre_close`(昨收) / `settle`(结算价) / `amount`(成交额) / `pre_settle`(昨结算) / `oi_chg`(持仓量变化)；由补源填充，**tbpy 主源写的行这些列留 NULL**，`data_source` 标记来源（不跨源伪造、不拿甲源值冒充乙源）。
  - **昨收双轨校验**：`pre_close`(源给) 与「前一交易日行的 `close`」应一致，不一致即为阶段二的脏数据信号。
  - **两源都取不到、故不落**：`avg_price`(均价)；`limit_up` / `limit_down`(涨跌停)——tbpy 返回空数组，openvlab 仅在 `product-exps` 给**当日**值（随价变动、属动态量，不落日线表，见 §七 Q8）。
  - `data_source`：该行数据来源（`tbpy` / `openvlab` / `tbpy+openvlab`），阶段二**按源分档核对**，不得混判。
  - 约束：`UNIQUE(symbol, bar_date)`，同合约同交易日唯一，防意外重复插入。
  - **抽取方法**：阶段一每日盘后据 `data_storage_rule`（`table_ref='contract_daily'`）预取 → `get_history_n(symbol, "1d", count=pull_count, flag=QuoteFlag.Null, fields=fields)` 拉不复权日线。`store_mode='incremental_upsert'`：**仅拉新 bar**（`pull_count=1`，见 §2.2），`UPSERT` 追加/更新该合约当日行、不回写历史；`date_type='bar'` 派生「收盘后为终态」（盘中 `bar_date==today` 行为临时值）。对照：`main_contract_daily` 用 `full_window_rewrite` 整窗重写、不可增量。

```sql
CREATE TABLE contract_daily (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol       TEXT,          -- 月合约代码，如 m2601.DCE
    product_cd   TEXT,          -- 标的代码（由 symbol 解析派生）
    expire       TEXT,          -- 到期月 YYYY-MM（由 symbol 解析派生）
    bar_date     TEXT,          -- 交易日 YYYY-MM-DD
    open         REAL,          -- 开盘价（不复权）
    high         REAL,          -- 最高价（不复权）
    low          REAL,          -- 最低价（不复权）
    close        REAL,          -- 收盘价（不复权）
    volume       REAL,          -- 成交量（手）← tbpy fields.volume / openvlab vol
    oi           REAL,          -- 持仓量（手）← tbpy fields.position / openvlab oi
    pre_close    REAL,          -- 昨收（tbpy 无源；openvlab 有值，与前一交易日 close 互校）
    settle       REAL,          -- 结算价（tbpy 无源；openvlab 有值）
    pre_settle   REAL,          -- 昨结算（tbpy 无源；openvlab 有值）
    amount       REAL,          -- 成交额（tbpy turn_over 实测空数组；openvlab 有值）
    oi_chg       REAL,          -- 持仓量变化（openvlab 有值）
    data_source  TEXT,          -- 该行来源：tbpy / openvlab / tbpy+openvlab（阶段二按源分档核对）
    -- 不落（两源都取不到）：avg_price / limit_up / limit_down（后者 openvlab 仅给当日值，属动态量，见 §七 Q8）
    UNIQUE (symbol, bar_date)
);
```

- **录入示例**（`store_mode='incremental_upsert'`，仅追加/更新新 bar，幂等）：
  ```python
  def store_contract_daily(conn, bars, source):
      # bars: 经 time(datetime)/trade_date → bar_date(YYYY-MM-DD) 格式化后的行；source: tbpy | openvlab
      # 主源 tbpy 写 OHLCV + oi；补源 openvlab 额外补 pre_close/settle/pre_settle/amount/oi_chg（COALESCE 只补不覆盖）
      conn.executemany(
          """INSERT INTO contract_daily
             (symbol, product_cd, expire, bar_date, open, high, low, close, volume, oi,
              pre_close, settle, pre_settle, amount, oi_chg, data_source)
             VALUES (:symbol, :product_cd, :expire, :bar_date, :open, :high, :low, :close, :volume, :oi,
                     :pre_close, :settle, :pre_settle, :amount, :oi_chg, :data_source)
             ON CONFLICT(symbol, bar_date) DO UPDATE SET
                open=excluded.open, high=excluded.high, low=excluded.low, close=excluded.close,
                volume=excluded.volume, oi=excluded.oi,
                pre_close =COALESCE(excluded.pre_close,  pre_close),
                settle    =COALESCE(excluded.settle,     settle),
                pre_settle=COALESCE(excluded.pre_settle, pre_settle),
                amount    =COALESCE(excluded.amount,     amount),
                oi_chg    =COALESCE(excluded.oi_chg,     oi_chg),
                data_source = CASE WHEN data_source = excluded.data_source THEN data_source
                                   ELSE 'tbpy+openvlab' END""",
          bars,
      )
  # 同日重拉：ON CONFLICT 命中 UNIQUE(symbol, bar_date) → 更新而非重复插入（幂等）
  ```
  单条样例（`m2611.DCE` 2026-10-16，取自 tbpy 实测真值）：

### 3.3 期权合约日线：option_daily

- **用途**：**逐期权合约的不复权日线真值**（权利金 + 成交 + 持仓）。选腿（#5 安全垫、#7/#8 封顶、#9 肥瘦）
  以本表 `close` / `oi` 为输入；**只存数据源真值，不存派生量**（派生列已清理，见下）。
- **数据源**：主源 **tbpy** `get_history_n(symbol=[...], frequency='1d', count=1, fields=[...])`
  （限流 1 次 / 60s，symbol 传 **list** 可一次带 ≤20 合约算 1 次查询 → **≤20/批 + 批间 62s 冷却**；
  与 D09/D10 同款）。盘后口径主值＝`close`。
  - **补源 openvlab `/api/history`（2026-10-17 实测）**：`GET /api/history?symbol=M2611C3000&resolution=1D&from={unix}&to={unix}`
    → **221 条期权日线**（`ts_code=M2611-C-3000.DCE`），字段与 §3.2 同构（含 `pre_close` / `settle` / `pre_settle` /
    `amount` / `oi_chg`），**无 60s 限流、可整链批量**。
    **坑**：期权 symbol 须用**大写紧凑格式** `M2611C3000`；小写 `m2611C3000` 会被**解析成标的**（返回 `M2611.DCE` 的期货日线），
    而 `M2611-C-3000` / `m2611-C-3000` 返回 0 条——静默错数据，取数后须以 `ts_code` 回校。

- **返回字段（`get_history_n` → 按 `fields` 名返回 `{symbol: {field: [值]}}`，实测 2026-10-16 00:17）**：

  | `fields` 名 | 类型 / 实测值（`m2611-P-3000.DCE`） | 落库 | 说明 |
  |---|---|---|---|
  | `open` | `float[]` `[0.5]` | → `open` | 开盘 |
  | `high` | `float[]` `[0.5]` | → `high` | 最高 |
  | `low` | `float[]` `[0.5]` | → `low` | 最低 |
  | `close` | `float[]` `[0.5]` | → `close` | 收盘＝**权利金主值**（不复权） |
  | `volume` | `float[]` `[568]` | → `volume` | 成交量（手） |
  | `position` | `float[]` `[14440]` | → `oi` | **持仓量**（即 `Bar.open_int`；`fields` 里叫 `position`） |
  | `time` | `datetime[]` `[2026-10-16 00:00]` | → `bar_date` | 该 bar 的交易日，转 `YYYY-MM-DD`；**陈旧判定键** |
  | `turn_over` | **实测空数组 `[]`** | **tbpy 侧不落** | 成交额 tbpy 取不到（3/3 样本皆空）；`amount` 改由 openvlab 补源填充 |
  | `rollover` | `float[]` `[1.0]` | **不落** | 复权因子；本表不复权，恒 1.0 无意义 |
  | `frequency` / `symbol` | **实测空数组 `[]`** | **不落** | 接口不填充 |

- **实测真值**：
  1. **新鲜 bar 样例**（`get_history_n` 全字段，2026-10-16 00:17 取）：
     ```
     m2611-P-3000.DCE : open=0.5  high=0.5  low=0.5  close=0.5  volume=568  oi=14440  bar_date=2026-10-16
     m2611-C-3000.DCE : open=296  high=296  low=279  close=279  volume=15   oi=1547   bar_date=2026-10-15
     m2611.DCE（期货）: open=3289 high=3291 low=3276 close=3278 volume=26256 oi=364376 bar_date=2026-10-16
     ```
     同一时刻、同一标的月：`P-3000` 已有 10-16 的 bar、`C-3000` 仍停在 **10-15** → 再一次印证
     **bar 日期必须逐合约判定**，不能按"取数日"统一认为新鲜。
  2. **陈年 bar 样例**（2026-10-15 22:28 `close_batch`）：
     ```
     m2611-C-2500 close=694.0 bar_date=2026-08-18   m2611-C-2600 close=744.5 bar_date=2026-09-15
     m2611-C-2650 close=656.0 bar_date=2026-09-29   m2611-C-2700 close=442.0 bar_date=2026-07-28
     m2611-C-2750 close=609.0 bar_date=2026-09-09
     ```
     深度实值 / 无成交合约最后一根 bar 距取数日 **17–79 天** → `close` **必须与 `bar_date` 同落**，
     下游判 `bar_date == 目标交易日`，否则把几十天前的收盘价当今日权利金（#7/#8/#9 全错）。
     这是 `UNIQUE(symbol, bar_date)` + **陈旧判定**的实测依据（处理方式见 §五 STALE 标注；
     是否升级为"不活跃即淘汰"见 §七 开放项）。
- **已删除的列（不落本表）**：`iv` / `delta` / `gamma` / `vega` / `theta` / `rho` /
  `theo_price` / `margin` / `status`（2026-10-15 清理）。
  **2026-10-17 复核纠正**：`settle` / `amount` / `pre_settle` **并非无源**——openvlab `/api/history` 实测全部有值
  （此前"不落"结论只验证了 tbpy，被误写成全局无源），故**补设回本表**，由补源填充并以 `data_source` 标记。
  依据＝**取不到 + 当前无消费者**（全代码检索 `checks/`：
  仅 `oi` 被 `c2_oi` 消费，greeks / theo_price / status / 合约级 iv 零命中）：
  - **tbpy 取不到**：`Instrument`(10) / `Tick`(14) / `Bar`(11) 全量实测**均无 iv、无 greeks、无保证金率、
    无结算价**；顶层 API 也无对应接口。
  - **外部源其实取得到（2026-10-17 实测纠正）**：openvlab `GET /api/dto/{品种}?exps={YYYYMM,…}` 直接给出
    **逐 strike 的 `iv` / `iv_bid` / `iv_ask` / `de`(delta) / `ve`(vega) / `ga`(gamma) / `th`(theta)**，
    以及 `a`/`b`(ask/bid)、`l`(last)、`v`(vol)、`o`(oi)、`f`(forward)、`t`(theo)、`cc`(合约代码)；
    **且非主力月同样有值**（实测 `M2701` 23 档，`m2701-C-3250` → `iv=12.51`、`iv_bid=11.93`、`iv_ask=12.79`、
    `de=0.5532`、`ve=5.288034`、`ga=0.00234`、`th=-0.776506`）。
    ⇒ **合约级 IV / greeks 无需反解**；但它是**期权合约级**行情数据，不并入标的级的 `option_iv`（§3.4），
    是否单独立表见 §七 Q9。新浪 `OptionService.getOptionData` 只给主力月 T 型盘口（代码仅取行权价阶梯）。
  - **`amount` tbpy 取不到**：`get_history_n` 的 `turn_over` 实测（期货 `m2611.DCE` + 期权 `m2611-C-3000` / `P-3000` 等）
    **全部返回空数组**；`amount` 改由 openvlab `/api/history` 补源供给。
  - **`pre_settle` tbpy 日线口径无源**：昨结算只在 tbpy tick 的 `Tick.pre_settlement` 有值，而**本系统不取 tick**
    （设计原则 4）；但 openvlab `/api/history` 日线**直接给 `pre_settle`** → 落表（补源列）。
  - **盘口 `bid` / `ask` 同理不落**：日线 `Bar` 本就没有这两个字段，且盘口只在交易时段有值；
    流动性改由日线代理判定（`volume` / `oi` / 最后成交日）。
  - **`margin` 随现价变、落库即过期**：#7 走 `c7_margin.estimate_candidate_margin()` **现算**
    （现价 × 乘数(D11) × 保证金率(D04) × 组合优惠(D05)），不读表；账户真实占用在
    `Position.l/s_use_margin_amount`（账户侧）。
  - 合约级 IV / greeks：**优先直接取 openvlab `dto` 的源真值**（见上）；仅当确实需要**自算反解**时才
    **另建派生表并带 `model` 标记**（Black-76 / CRR / BAW + 输入快照），不混进本表"真值"语义——
    避免阶段二把模型值当行情真值做硬判定。
- **抽取方法**：阶段一盘后按标的拉全链 → 逐合约 `UNIQUE(symbol, bar_date)` 真 upsert（增量追加新 bar）。
  **盘中拉到的行属"形成中 bar"**（`bar_date`=当日、`close` 非定稿）：按 §五 规则，下游指标计算排除、
  收盘后 `use_cache=False` 强制重拉回填。
- **字段语义**：`bar_date`＝该行价格所属交易日（**陈旧判定键，不是取数日**）；价格一律**不复权**；
  `NULL` 即 MISSING（§八 四态原则）。
- **命名对照 · 持仓量（同一事物三个名字，勿混）**：

  | 层面 | 名字 | 说明 |
  |---|---|---|
  | tbpy 取数参数 | `fields=['position']` | `get_history_n` 里必须写这个**字面量** |
  | tbpy 返回对象 | `Bar.open_int` | 类属性名（对象里不叫 position） |
  | 本库列名 | **`oi`** | 全库统一：`main_contract_daily` / `contract_daily` / `option_daily`；#2 检查 `c2_oi.py`、`ThresholdSet.oi_min` 同口径 |

  **列名不用 `position`**：该词在本系统已专指**账户持仓**（`account_position` 表、`tbpy.Position` 类，
  字段 `l_current_volume` / `s_use_margin_amount` …）；若日线列也叫 `position` 便成"一名两义"
  （**市场未平仓量** vs **我账户里的持仓**）。`oi`＝Open Interest，行业通用缩写、无歧义。

```sql
CREATE TABLE option_daily (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    symbol         TEXT,  -- 期权合约代码（→ option_info.symbol）如 m2611-C-3000.DCE
    product_cd     TEXT,  -- 标的品种码（→ future_info.product_cd），便于按品种整链扫描
    bar_date       TEXT,  -- 该行价格所属交易日 YYYY-MM-DD ← fields.time（陈旧判定键）
    open           REAL,  -- 开盘 ← fields.open [可拉尽拉]
    high           REAL,  -- 最高 ← fields.high [可拉尽拉]
    low            REAL,  -- 最低 ← fields.low [可拉尽拉]
    close          REAL,  -- 收盘价（不复权）← fields.close，权利金主值
    volume         REAL,  -- 成交量（手）← fields.volume
    oi             REAL,  -- 持仓量（手）← fields.position（即 Bar.open_int）
    pre_close      REAL,  -- 昨收（tbpy 无源；openvlab /api/history 有值）
    settle         REAL,  -- 结算价（tbpy 无源；openvlab 有值）
    pre_settle     REAL,  -- 昨结算（tbpy 仅 tick 有源、本系统不取 tick；openvlab 日线有值）
    amount         REAL,  -- 成交额（tbpy turn_over 实测空数组；openvlab 有值）
    oi_chg         REAL,  -- 持仓量变化（openvlab 有值）
    data_source    TEXT,  -- 该行来源：tbpy / openvlab / tbpy+openvlab
    UNIQUE (symbol, bar_date)
    -- 不落：rollover(复权因子，恒 1.0) / frequency·symbol(接口不填充) / bid·ask(盘口，本系统不取 tick)
    -- 不落：iv / greeks（属期权合约级市场数据，直接取 openvlab dto；不并入本表日线真值，见 §七 Q9）
);
```

### 3.4 隐含波动率日线：option_iv

> **2026-10-17 重写**：实测 openvlab 存在**历史 ATM IV 序列端点**（此前只用过 `ctamap-all` / `product-exps` 两个接口，
> 故误判"无历史、须每日攒快照"）。本表由「时点快照档」改为**日线档**（`date_type='bar'`），一次可拉满约一年序列，
> **IV 分位本地可算**，openvlab 自算的百分位降级为交叉校验值。全库自此**无 tick / 快照档**业务表（设计原则 4）。

- **用途**：**平值隐含波动率（ATM IV）日线**，按「品种 × 标的合约（=到期月）× 交易日」组织。消费者＝`#4 IV 判据`
  （分位门槛 + 方向）与 `#5 安全垫`（非主力月 IV）。相对估值与择时（IV 高位卖、低位买）。
  **口径键**：`bar_date`（交易日，含夜盘归属规则——实测 `history-atmvol` 末条 `2026-10-19` 即周五夜盘归属的下周一），
  与其余日线表同一套主键语义；`exp` 区分到期月，**主力月只是 `exp` 的一个取值**（不再"只覆盖主力月"）。
- **数据源**：**openvlab（纯公开 HTTP JSON，无需登录 / 浏览器 / token）**，三个端点分工：
  | 端点 | 取什么 | 粒度 / 深度 |
  |---|---|---|
  | `GET /api/history-atmvol?symbol={标的合约}&resolution=1D&from={unix}&to={unix}` | **历史 ATM IV 序列** `[[bar_date, atmv], …]` | 每 (品种, 到期月) 一条序列，**深度上限 222 个交易日（≈1 年，起点 2025-11-17）** |
  | `GET /api/ctamap-all` | 当日全市场主力月快照：`atmv_current` / `atmv_percentile` / `atmv_1dchg` / `skew_current` / `skew_percentile` / `rv22` / `price` / `carry` / `valphaT` / `ctn` / `frontfwd_mom` / `exp` / `expiry_date` / `last_time` | 79 个标的（含 8 个 ETF 期权） |
  | `GET /api/volatility-ts-all` | 全品种 × **全到期月** `atmvol_tday` / `atmvol_yday` + `sum_oi_call` / `sum_oi_put` + `days_to_expiry` | 一次拿全各月 IV，无需逐月循环 |
  **注**：tbpy 无 iv 字段（`Tick`/`Bar`/`Instrument` 实测均无），"由 `option_daily` 逐合约 iv 聚合"**不成立**；
  合约级 IV／greeks 若需要，取 `GET /api/dto/{品种}?exps={YYYYMM,…}`（逐 strike 给 `iv` / `iv_bid` / `iv_ask` /
  `de` / `ve` / `ga` / `th`，**且非主力月同样有值**），但那是**期权合约级**数据，不并入本表（本表是标的合约级）。
- **抽取方法**：阶段一盘后按 `(product_cd, exp)` 遍历 `data_storage_rule` 所列的到期月 → 拉 `history-atmvol`
  （`pull_count` 一次覆盖全窗）→ `UNIQUE(product_cd, exp, bar_date)` 真 upsert；当日再用 `ctamap-all` /
  `volatility-ts-all` 补**当日行**的 `skew*` / `rv22` / `price` / `carry` / `valphaT` / `atmv_percentile`
  （这些**只有当日有源**、历史行为 NULL，不伪造）。
  **终态**：`bar_date` 早于当前交易日的行为终态；`bar_date == 当前交易日` 的行为**形成中**（盘中 ATM IV 仍会变），
  按 §五『形成中 bar』排除出指标、收盘后重拉定稿。
- **取数坑（实测，务必遵守）**：
  1. `resolution` **必须传 `1D`（大写 D）**（与 §3.2 `contract_daily` 补源同款坑）；`1d` / `D` 静默返回空数组。
  2. `symbol` 传**标的期货合约**（`M2611`，大小写不敏感），**不是品种代码**——`M` / `M_O` / `OPT_DCE_M` 全部返回空。
  3. 期权合约 symbol（`M2611C3000`）传 `history-atmvol` 只会返回**当日 1 条**（被映射到其标的的 ATM IV），
     **合约级 IV 历史无源**。
  4. 远月无成交的到期月（实测 `M2708` / `M2709`）返回 0 条，如实留空、不填历史值。
- **IV 分位（#4）**：**本地自算为主**，公式（N 日窗口，取本表 `atmv` 序列）：

  \[
  \mathrm{IVP} = \frac{\#\{d \le N : atmv(d) < atmv(今日)\}}{N} \times 100
  \]

  **实测对账（M2611，2026-10-17 取数，当前 `atmv=13.22`，样本 min 10.58 / max 30.09）**：

  | 窗口 | 实得点数 | 本地分位 | openvlab `atmv_percentile` |
  |---|---|---|---|
  | 250 自然日 | 164 | 22.56% | — |
  | 365 自然日 | 222 | 27.03% | — |
  | openvlab 自算（≈1 年） | — | — | **24.69%** |

  三者同量级 → 本地值可用；差异来自窗口定义（自然日 vs 实际点数、是否含当日、ATM 定义），
  **openvlab 值仅作交叉校验**，不再是唯一来源。

```sql
CREATE TABLE option_iv (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，标识数据写入先后
    product_cd       TEXT,   -- 品种代码，如 M
    exp              TEXT,   -- 标的合约到期月 YYMM 4 位如 2611（口径键；与源 symbol M2611 / option_info.underlying_month 同格式；主力月只是其中一个取值）
    bar_date         TEXT,   -- 交易日 YYYY-MM-DD（含夜盘归属，非取数日）
    atmv             REAL,   -- 平值隐含波动率 %（全历史有源，history-atmvol）
    atmv_1dchg       REAL,   -- 平值隐波日变（可由序列自算；openvlab 亦给当日值）
    atmv_percentile  REAL,   -- IV 百分位 0-100（openvlab 自算≈1年窗口，仅当日行有值；本地另算，见上）

    price            REAL,   -- 标的现价（仅当日行有值）[可拉尽拉]
    carry            REAL,   -- 展期收益（仅当日行有值）[可拉尽拉]
    valphaT          REAL,   -- 波动率 alpha（仅当日行有值）[可拉尽拉]

    UNIQUE (product_cd, exp, bar_date)
    -- 不落（无源）：iv / iv_atm（与 atmv 同义重复）；hv_20 / hv_60（openvlab 只给 rv22，
    --   历史波动率应由 main_contract_daily 收益率派生、属派生列不落真值表）；

);
```

## 四、字段约定

- **口径**：`（后复权）`仅用于相对指标；`（不复权）`用于绝对价。混合即缺陷（需求文档 §二.1）。`main_contract_daily` 存**服务端后复权价**（换月后复权，来自 `RolloverBackWard`），其列注释标"（后复权）"；因后复权保值收益率，相对指标与锚定日无关（见 §三.1 / §五 复权锚定）。
- **单位**：价格=元；成交量=手；**金额一律=元**（含 `future_info.margin_per_lot` / `actual_margin_per_lot`，已由权威源万元 ×10000 归一，禁止万元/元混算）；`pct`/`_degree`=百分比；**本库业务表无 greeks 列**（`tbpy.Position` / `Bar` / `Instrument` 实测均无，2026-10-17）；
期权合约级 greeks 直取 openvlab `dto`（§3.3 注、§七 Q9），**自算反解的**派生 greeks 若将来落地须**另表带 `model` 标记**，不混进真值表。
- **`[可拉尽拉]`**：表示数据源可取到、但当前策略暂未消费，仍**一律落库**，以备后续分析。
- **时间**：`bar_date` = **数据自身日期**（bar 的交易日，`YYYY-MM-DD`），是**全部业务表**的分区 / 索引键（`option_iv` 亦按 `bar_date`，2026-10-17 日线化）；`pull_date` = **拉取动作发生日**（与数据内容无关），仅 `data_pull_detail`（及 account 表，账户快照即当日拉取）使用。**本库不再有 `snapshot_time` 维度**——源侧时点仅作**元数据**留存（`option_iv.last_time`，标"这份数据截止到源端哪一刻"，不参与主键 / 老化）。
- **数值精度**：数值字段统一用 `REAL`（价格 / 金额 / 比率 / greeks 等），**不**采用 INTEGER 最小单位方案（如"分"），以免引入 100 倍换算错误、且仍无法精确表达 0.0001 元价格。REAL 的浮点残差在**比较 / 累加处做好控制**：金额按业务精度四舍五入（如到分）、价格按最小变动价位；避免大量浮点连加；相等比较用 epsilon。
- **自增 id**：所有业务数据表首列统一加 `id INTEGER PRIMARY KEY AUTOINCREMENT`，仅用于标识数据写入先后、便于排查；原业务复合/单列主键**一律降为 `UNIQUE` 约束**保留去重语义（控制面 `data_storage_rule` / `data_state_check` / `data_pull_detail` 同样必须补 `UNIQUE`，否则 id 抢占主键后去重凭空消失）。**例外**：KV 表 `global_config` 与静态表 `future_info` / `option_info` 以业务键为 `PRIMARY KEY`，不加自增 id（其余表——含 `trading_calendar`——均带自增 `id`）。
- **id 稳定即"先后"（重取纪律）**：`id` 要真实代表首次写入顺序，重取/重跑**必须用 `ON CONFLICT(业务 UNIQUE 键) DO UPDATE`（真 upsert，id 不变），禁用 `INSERT OR REPLACE`**（后者删+插会发新 id，打乱"先后"）。

## 五、关键关系与口径

- **离线分析前提（见设计原则 1）**：本系统是**离线分析**系统（预取 → 质检 → 候选清单 → 人工执行），**不存在实时消费路径**。故以下各条的"新鲜度 / 未定稿"处理，一律是**标注 + 提示**（供人工复核），**不是淘汰候选**；执行价与分析价的偏差可接受，但报告必须标注数据日期（`bar_date`）。
- **三类时序数据约束（总览）**：本系统行情数据存在三类时序一致性问题，分别由下方专条约束——① **后复权锚漂移（事件驱动、对相对指标无碍）**：`main_contract_daily` 后复权绝对水平**并非每拉必变**，仅当两次拉取间隔内发生换月时历史事件的水平才会重算漂移；但后复权保值收益率，**相对指标与锚无关**，且本表仅用于相对指标，故实际无碍（见『复权锚定』）；落库存后复权价、相对指标单锚计算即可（整窗重写天然同锚）。② **形成中 bar**：取数时点若落在交易时段内，日线类 `bar_date == today` 行是收盘前临时值（见『形成中 bar』）；③ **IV 已日线化（2026-10-17）**：`option_iv` 由「时点快照档」改为**日线档**（openvlab 有历史 ATM IV 序列，见 §3.4），同样按 `bar_date` 判终态与老化 —— **本库已无时点 / 快照档业务表**。**盘口 / tick 不落库**（设计原则 4）。三者共同决定：哪些数据能落库、以何主键、何时为终态、相对指标须在同一锚 / 同一终态窗口内计算。
- **table_ref 关联（1:1）**：`data_state_check.table_ref` = `data_storage_rule.table_ref`，两表经此**一对一**关联（一个取数单元契约行 ↔ 一张表的当前状态行）；`data_state_check` 以 `bar_start_date` / `bar_end_date` 标识其核对覆盖的数据区间（而非拉取日），对账出"应有 vs 实有"。
- **品种关联**：业务表 `product_cd`（品种）/ `symbol`（合约）关联 `future_info.product_cd`，取乘数 / 保证金金额（单腿 `margin_per_lot` / 实际占用 `actual_margin_per_lot`，见 §2.5）。
- **时间维度 / 分区**：业务表**一律**含 `bar_date`（数据日期），跨日自动失效，不拿旧数据当新；`option_iv` 亦按 `bar_date`（并以 `exp` 区分到期月），**本库无快照维度表**。控制面 `data_state_check` **不存 `pull_date`**，改以 `bar_start_date` / `bar_end_date` 标识其核对覆盖的数据区间（描述"齐了哪段数据"，而非"哪天拉的"）。
- **价格口径**：`main_contract_daily` 后复权（相对指标），其余不复权（绝对价）——检查逻辑须严格分流。
- **终态性与四态映射**：日线类（`bar`）**收盘后为终态** → 检查程序据此将 `status` 置 `normal`；盘中 `bar_date==today` 的形成中 bar 视为"尚未定稿"，`status` 停留在 `fetching`（等待），不消费未定稿数据，收盘后重拉定稿再转 `normal`。`option_iv` 已归 `bar` 档（2026-10-17 日线化），终态判据与其余日线表一致（当日行为形成中、收盘后定稿）；`static`（如 `trading_calendar`）存在即终。`normal`/`abnormal` 的具体判定由检查程序按 `date_type` 实现（见 §2.3）。
- **静态档就绪判据（检查程序实现）**：`date_type='static'`（如 `trading_calendar`）以**完整性**核对（覆盖预期区间 / 存在即终），非每日计数，判 `normal`/`abnormal`。
  **原「时点档就绪判据」已随 `tick` 档取消**（2026-10-17）：`option_iv` 改按 **bar 档**以「区间内实际交易日数 × (品种 × 到期月) 实体数」计数核对。
  **日线档的"陈旧"仍只作 STALE 标注**：有行但最新 `bar_date` 落后于目标交易日 → **提示并在报告中标注数据日期**，
  **仍可消费、不判 `abnormal`、不淘汰候选**（离线分析本就用最近可得数据，见设计原则 1）；完全无行才 `abnormal`（下游按 MISSING 处理）。
- **形成中 bar（取数时点落在交易时段内）处理**：日线类 `bar_date == today` 行是**形成中 bar**（`close` 非当日最终收盘），**不得直接用于相对指标 / 绝对价结论**。三层处理：(a) **读侧**：对 `bar_date == today` 且未过收盘时点的行硬判"形成中"、排除出 #3 市况 / #10 否决等指标，最新有效点取上一已完成交易日；(b) **门控**：阶段二判 `bar` 收盘前为形成中，将当日 `data_state_check.status` 维持在 `fetching`（视为尚未定稿、等待），阶段三消费时**标注"未定稿"**并建议收盘后重跑定稿（离线分析：结论照出、如实标注，不做"盘中粗筛 vs 盘后定稿"两套口径）；(c) **回填**：收盘后阶段一以 `use_cache=False` 对刚收盘交易日**强制重拉回填**，定稿后检查程序将 `status` 转 `normal`。
- **IV / greeks 的供给定位（2026-10-17 重写）**：日线 `Bar` **没有 IV**（tbpy `Instrument` / `Tick` / `Bar` 实测均无），
  IV 与 greeks 由 **openvlab 公开 HTTP 接口**供给，且**已可历史化**：
  (a) **标的级 ATM IV** → `option_iv`（§3.4），按 `(product_cd, exp, bar_date)` 日线落库，一次拉取可覆盖约 **222 个交易日**，
  **IV 分位本地自算**（不必逐日攒快照）；(b) **期权合约级 IV / greeks** → openvlab `dto` 逐 strike 直给
  （`iv` / `iv_bid` / `iv_ask` / `de` / `ve` / `ga` / `th`，**非主力月同样有值**），属期权合约级行情数据，见 §七 Q9；
  (c) **分析消费口径**＝取目标交易日那一行并**标注 `bar_date`**（设计原则 1），不追求实时。
  **盘口（tick）为何不落库**：`bid`/`ask` 只能来自 `get_current_tick`，而它①只在交易时段有值（盘后必然为空，
  与"离线分析盘后跑"直接冲突）；②60s 限流、单次 ≤20 合约，全链拉取代价高；③**没有报价的合约本就不可交易**
  （应淘汰，无需记录）。故盘口不建表、#1 盘口价差不作为检查项；流动性改由**日线事实**判定：
  最后成交日是否够新（`bar_date`）、当日 / 近期 `volume`、`oi`（#2）——这些在盘后一样拿得到、且是终态。
- **复权锚定（后复权序列的时点依赖）**：`main_contract_daily` 存**服务端后复权价**（来自 `RolloverBackWard`）。后复权为**乘性平移、保值收益率**：同一连贯拉取内任意两日之比 = 真实收益率，**与锚定日无关**；本表为 `full_window_rewrite`（整窗 DELETE + 全窗 INSERT），同标的每次拉取天然共用同一锚，不存在跨锚混算。故本表**仅用于相对指标**（收益率 / ADX / 区间位置），锚对其**无实质影响**；只有"拿后复权绝对价当价格"才会出错（已被"价格口径两分"铁律禁止）。处理：(a) 落库存**服务端后复权价**，弃用原始价 / 调整因子方案——tbpy `QuoteFlag` 仅 `RolloverBackWard` 一个复权枚举、无独立"原始价" flag（原始价需 `flag=None` 额外拉取，且对相对指标无益），故只拉一次 `RolloverBackWard` 即可；(b) 不复权表（`contract_daily` / `option_daily` 的 OHLC）是真实成交价、不随锚定日变，无此问题（本系统不落 tick，故无 tick 快照与本条的关系）。（**实证**：本机 `strategies/sell_option/sell_option/data/daily.db` 的 `index_daily` 表（v1 旧名，本设计对应 `main_contract_daily`）中，`m9888.DCE` 在 `2026-09-30` / `10-08` / `10-09` 三次拉取的 298 个共同历史日，后复权收盘价**完全一致**——实测无漂移，印证整窗单锚下相对指标安全。）
